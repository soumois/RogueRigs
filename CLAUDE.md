## Claude-specific
- The owner starts crew work with `/task <request>` (`.claude/commands/task.md`). Without it, the main session still follows the same workflow for any request that produces game content, code or assets: it only relays. First it picks the request family from the owner sentence (`request-families`, step 0 of `task.md`): réglage (a setting on an existing system, no new asset or system, no design choice), comportement (new or changed behaviour or system), visuel (a look to find), gros morceau (larger than one standard task). The owner words `réglage`, `comportement`, `visuel`, `gros` force it. It states the family in one line (`Famille : <family> (<reason>)`) before launching anything. Réglage: no planner; it runs `node vault/scripts/task-reglage.js "<owner words>"` and launches one fresh `executor` on the printed id; on a wrong-family report from that executor it relaunches through the planner. Other families: it launches the `planner` agent (`agent-planner`, protocol steps 0 to 4), relays the owner's questions and answers (on a pure "ok" / "tout par défaut" it runs `node vault/scripts/task-confirm.js <Saved/Planner/<first-global-id>.defaults.json> "<owner words>"` instead of resuming the planner; any other answer, or a missing file, resumes it), then launches one fresh `executor` agent per confirmed global task (`agent-executor`, steps 5 and 6): one Opus agent that does the whole task itself and launches only `style-guide`. It never plans or executes itself.
- Sub-agent definitions live in `.claude/agents/`: only `planner`, `executor` and `style-guide` (owner 2026-11-11, task-503); each one points to its node in `vault/reference/agents/`. The other `agent-*` nodes are role rules the executor applies itself.
