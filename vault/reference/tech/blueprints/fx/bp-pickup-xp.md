- pulse_desync_inputs (task-257-01, owner 2026-10-20, read by the C++ subtask 257-02): M_XPNutGlow got two per-object inputs so crystals and pickups do not pulse together. Sine argument (period 1, so turns) = Time x (PulseFrequency x PulseRate) + dot(ObjectPositionWS, (0.0137, 0.0211, 0)) + PulsePhase; the position term stays. PulsePhase (turns, 0..1) = PerInstanceCustomData index 4 (default 0) + scalar parameter PulsePhase (Custom Primitive Data index 1, default 0); PulseRate (scale of PulseFrequency) = PerInstanceCustomData index 5 (default 1) x scalar parameter PulseRate (Custom Primitive Data index 2, default 1). One parent serves both: the pickups (static mesh) write Custom Primitive Data 1 = phase and 2 = rate (SetCustomPrimitiveDataFloat; 0 is GlowFadeDataIndex, the glow disc); the instanced deposit meshes write per-instance custom data 4 = phase and 5 = rate (SetCustomDataValue; 0 console mark, 1-3 ore colour; their ISM needs NumCustomDataFloats of at least 6). On a static mesh the PerInstance node returns its default, on an instanced mesh a missing or unset slot returns its default, so each source is neutral where unused. Neutral (phase 0, rate 1, data absent): identical to the former expression, so MI_OreChunk_*, MI_DuskiteDeposit_Crystal, MI_HealCrystal_*, M_XPNut_hole, M_XPCube_core_* and the chip cores are unchanged. Nodes changed: Multiply_1 (Time x PulseFrequency) input B was PulseFrequency, now Multiply_5 (PulseFrequency x Multiply_4 (PerInstance 5 x PulseRate)); the Sine input was Add_0, now Add_3 (Add_0 + Add_2 (PerInstance 4 + PulsePhase)). Added: PerInstanceCustomData_0 and _1, ScalarParameter_4 and _5, Add_2, Add_3, Multiply_4, Multiply_5. Recompiled without error and saved; on-screen look and runtime reading of the data not checked. Writers (task-257-02): ore and heal pickups in [[sys-pickups-lifecycle]] (pulse per life), crystal instances in [[sys-grid-deposits]] (pulse desync); BP_PickupXP and BP_PickupXPBig keep the neutral values (nothing written).
