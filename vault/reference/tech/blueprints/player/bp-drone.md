# BP_Drone

- asset_path: /Game/RogueRigs/Blueprints/Player/BP_Drone
- parent_class: ARRDrone (/Script/RogueRigs.RRDrone)
- purpose: the visible helper drone, spawned by the miner from its `DroneClass`; visuals only, all logic in C++ ([[sys-drone]]).
- components (task-253-02, read back): inherited `Mesh` (root, the base), children of `Mesh`: `LaserPivot`, `AntennaMesh`, `ThrusterLeft`, `ThrusterRight` (Niagara, C++ defaults), plus `LaserMesh` (cutting laser, hidden outside Dig and Hack) and `DigImpactComponent` (Niagara, NS_DigImpact); none added in the Blueprint.
- exposed_defaults: Mesh StaticMesh = /Engine/BasicShapes/Sphere, RelativeScale3D (0.4, 0.4, 0.4) = 40 uu, OverrideMaterials[0] = MI_GB_Drone; C++ defaults kept (HoverHeight 150, FollowInterpSpeed 10; OrbitRadius and OrbitPeriod were never overridden and were removed from C++ in task-247-01, replaced by the escort properties, [[sys-drone]]). The PIE orbit reading under verified predates the escort movement. The task-248-01 wall properties (`Drone|Walls`, `DigHoverFaceDistance`, `DigHoverHeight`) are not overridden; no Blueprint edit. The task-249-01 alive properties (`Drone|Alive`, new `EscortBobAmplitude` default 9) are not overridden either; `HoverHeight` is now the hack height only, the Orbit height comes from `EscortCalmHeight` / `EscortAlertHeight`; the actor rotation is set by C++ every tick (the grey-box sphere shows none of it). No Blueprint edit. Task-251-01 replaced the escort properties by the patrol ones (`Patrol*`, `MinerRestSpeed`, `PatrolFallbackRetryInterval`, [[sys-drone]]); the removed escort properties were never overridden, the new ones are not; no Blueprint edit. LaserMesh StaticMesh = /Engine/BasicShapes/Cylinder, OverrideMaterials[0] = MI_GB_Laser.
- parts (task-253-01, note only, no Blueprint edit): C++ adds the inherited components `LaserPivot` (laser arm, child of `Mesh` at (1.606, 0, -17.248), pitched by C++) and `AntennaMesh` (child of `Mesh` at (-4.257, -0.837, 28.752), spun by C++), both empty (no mesh) until a bp subtask assigns SM_DroneLaser and SM_DroneAntenna, and SM_DroneBase on `Mesh` (whose 0.4 sphere scale the children inherit until then); the beam now starts at the laser emitter tip ([[sys-drone-parts]]).
- thrusters (task-254-02, note only, no Blueprint edit): C++ adds the inherited Niagara components `ThrusterLeft` and `ThrusterRight` (children of `Mesh` at the provisional `ThrusterLeftOffset` (0, -27, -17) and `ThrusterRightOffset` (0, 27, -17)), playing NS_DroneThruster through the C++ constructor default `ThrusterSystem`; C++ activates them and writes `User.Speed` every tick ([[sys-drone-parts]], [[bp-drone-thruster]]). Task-254-03 measured the nozzles on SM_DroneBase and set the Blueprint class defaults `ThrusterLeftOffset` (2.4, -27.7, -16.6) and `ThrusterRightOffset` (2.4, 27.7, -16.6), rotation 0, scale 1 (exhaust along -Z), see the thrusters_task_254_03 line.
- thrusters_task_254_03: measured in headless Blender on Art/Meshes/drone/SM_DroneBase.fbx (read only), lowest ring of each pod (vertices within 1 cm of the pod lowest z): Blender +Y pod lowest z -15.597, ring centre (x 2.43, y 27.67), x range -0.63..5.41, y range 24.58..30.77; Blender -Y pod lowest z -15.591, ring centre (x 2.38, y -27.94), x range -0.65..5.46, y range -30.90..-24.58. The pods end at z -15.6 (the -17.25 bounds minimum belongs to the central laser mount, not the pods; no nozzle sticks lower). Unreal axes (Y mirrored): left = Blender +Y = Unreal -Y. Offsets set: left (2.4, -27.7, -16.6), right (2.4, 27.7, -16.6), 1 cm under the lowest z, centred on the ring bounding box; they differ from the C++ defaults (0, +-27, -17) by 2.4 cm in X, so they are overridden in BP_Drone. Read back on the saved CDO: both offsets, `ThrusterSystem` = NS_DroneThruster; compile_blueprint no error. The CDO components `ThrusterLeft` and `ThrusterRight` read bAutoActivate false, Asset None and the constructor location (0, +-27, -17): the Blueprint offsets are applied by C++ `OnConstruction` to each instance and the asset is set at runtime, so the instance location was not read in PIE. Not verified: the look, the PIE instance location, the attach parent (not readable through MCP; set in C++ with SetupAttachment(Mesh)).
