# BP_ArenaGrid

- asset_path: /Game/RogueRigs/Blueprints/Terrain/BP_ArenaGrid
- parent_class: ARRArenaGrid (/Script/RogueRigs.RRArenaGrid)
- purpose: turns the C++ grid into the M1 grey-box asteroid; dropped in a level, it builds the terrain from the layout.
- components: inherited from C++ only (GridRoot and one hierarchical instanced mesh per cell type: floor, rock, ore, heal ore, special ore, barrel); none added.
- exposed_defaults: LayoutName = arena_m1; FloorMesh, RockMesh, OreMesh, HealOreMesh, SpecialOreMesh, BarrelMesh = /Game/RogueRigs/Art/Barrel/SM_Barrel (task-107-02; FloorMesh, RockMesh, OreMesh, HealOreMesh, SpecialOreMesh = Cube); OrePickupClass = BP_PickupOre_C; HealPickupClass = BP_PickupHeal_C; FloorMaterial = /Game/RogueRigs/Environment/Floor/MI_FloorCartoon (task-470-01, was MI_FloorPlates of task-273-03, before that MI_GB_Floor; revert = set it back, see [[bp-floor-plates-material]]); RockMaterial = MI_GB_Rock; OreMaterial = MI_GB_Ore; HealOreMaterial = MI_GB_HealOre; SpecialOreMaterial = MI_GB_SpecialOre; BarrelMaterial = /Game/RogueRigs/Art/Barrel/MI_Barrel_body (overrides slot 0 only); CellSize 200, BlockHeight 100, FloorThickness 200, MeshBaseSize 100 (C++ defaults).
- events: none.
- logic_in_bp: none
- assets: /Engine/BasicShapes/Cube; materials in /Game/RogueRigs/Materials/GreyBox/. Since task-016-03 the rock, ore, heal ore and special ore instances MI_GB_* derive from M_GreyBoxMarked (same Color and Roughness parameters as M_GreyBox) which adds a pulsing white emissive (sine of Time, 0.2 to 1, times 3) multiplied by PerInstanceCustomData 0: marked blocks (custom data 1) pulse white, others stay unchanged ([[sys-objectives]]). Verified in PIE: 1 marked instance of the rock HISM held custom data 1; pulse not viewed on screen.
- fine grid look (task-029-06): CellSize is 67 and the grid is 240 × 240 (`arena_m1_fine`); no Blueprint default changed. `M_GreyBoxMarked` (parent of rock, ore, heal ore and special ore instances) now multiplies its `Color` by a block shade: a Custom node (BlockShade) from the mesh UV and `PerInstanceRandom` gives each instance a brightness of 0.85 to 1.15 and darkens the face border (smoothstep 0.36 to 0.5 of the distance from the face center, down to 50 %), so single 67 uu blocks read as separate beveled stones with a seam. The marked pulse (emissive times custom data 0) is unchanged and still covers the whole face. Floor and barrel stay on `M_GreyBox` (no shade). Per-instance rotation is not available (C++ would have to rotate instances, not done).
- barrel assets (task-107-02), all in /Game/RogueRigs/Art/Barrel/: SM_Barrel (498 tris, 9 slots in order M_Barrel_body, ring, lid, cap, cap_edge, lid_edge, ring_edge, sticker, warning; bounds 90 x 90.27 x 134, bottom pivot; collision removed; LightMapCoordinateIndex set to 1 because the import generated an extra UV channel 2, which cannot be disabled through MCP); textures T_WearMask (sRGB off, TC_Masks, wrap), T_Barrel_Sticker, T_Barrel_Warning (sRGB, alpha); master M_BarrelPaint (parameters Color, LightColor, MaskStrength; BaseColor = lerp(Color, LightColor, (1 - T_WearMask.R) * MaskStrength) on UV0, roughness 0.7); instances MI_Barrel_body, ring, cap_edge, lid_edge, ring_edge (MaskStrength 0, flat colour) and MI_Barrel_lid, MI_Barrel_cap (MaskStrength 0.6); M_Barrel_sticker (opaque) and M_Barrel_warning (Masked, opacity mask = texture alpha). BarrelCollisionMesh untouched. task-197-03: M_BarrelPaint now adds an emissive fuse blink from barrel custom data index 4 (see [[barrel-asset]]); no grid property changed. Level instance inherits (no override); barrel instance count 16 unchanged; no screenshot taken, look not viewed.
- rock_slab_assign (task-230-11, provisional): 15 static meshes imported by MCP `StaticMeshTools.import_file` (no materials, combined) into /Game/RogueRigs/Environment/Rock/, Nanite on, slot 0 = MI_RockSlab. Intact SM_RockSlab_<Shape>_01 (Full 2 tris, Edge 43, Outer 42, Inner 58, Diagonal 86; 2 UV channels). Broken SM_RockSlabBroken_<Shape>_01/_02 (Full 208/200, Edge 204/228, Outer 120/120, Inner 364/386, Diagonal 404/346 tris; 4 UV channels UV0 to UV3, UV4 BlockC rim flag dropped by Nanite's 4-channel limit). Build settings set in the open editor (`py` console command, same settings as `static_mesh_build_settings.py`): Generate Lightmap UVs off, full precision UVs on, LightMapCoordinateIndex 1; render data read back: UV2 holds block centres (x -0.28 to 0.28, y 0.72 to 1.28, V flipped by the import) with one distinct value per block, UV3 seed and radius, so UV2/UV3 are not overwritten. Scale 67 x 67 x 100 uu as expected. Defaults set on BP_ArenaGrid: RockPieceMeshes (one mesh per shape), RockPieceBrokenMeshes (variants _01 and _02 per shape), RockPieceMaterial = MI_RockSlab, RockPieceBrokenMaterial none (falls back), bRockPieceImportFlipsY = true (confirmed: the imported Outer piece spans x -9 to 33.5 and y -33.5 to 9, canonical corner C (+, +) became (+, -)), HealOreCrystalMaterial = MI_HealCrystal_Bright, OreCrystalMaterial none, OreCrystalMesh SM_OreChunk_01 (C++ default). Why: the grid applies a crystal material to every slot of the mesh, and SM_OreChunk_01 has two slots (crystal_bright, crystal_dark); null keeps MI_OreChunk_Bright and _Dark, so ore keeps its violet two-tone look, while heal ore gets one red material (bright) on both slots. Blueprint compiled and saved. Look on screen and the first placed piece orientation in game are checked in [[task-230-12-rock-slab-check]].

The level instance showed a stale None until the map was reloaded in the editor. Read back in PIE after reload: OreInstances chunk OverrideMaterials = [MI_OreChunk_Bright, MI_OreChunk_Bright]. Render look checked in task-230-17 (not verified here).
