# Player — classes

  - `ARRMiner : ACharacter, IAbilitySystemInterface` (`RRMiner.h`): `URRAbilitySystemComponent` plus `URRHealthAttributeSet`, `URRMovementAttributeSet`, `URRPlayerAttributeSet` as default subobjects (registered by the ASC's `InitializeComponent`), and `URRProgressionComponent` `Progression` (`GetProgression()`, [[sys-progression]]), `URRUpgradeComponent` `Upgrades` (`GetUpgrades()`, [[sys-upgrades]]), `URRLevelUpComponent` `LevelUp` (`GetLevelUp()`, [[sys-level-up]]). Spring arm with absolute rotation (never turns with the pawn) and camera. Editable: `BaseStatsRowName` (`Miner`), `CameraPitch` (−50), `CameraYaw` (0), `CameraArmLength` (1400, provisional, owner 2026-10-20, to test, was 1700), `bCameraLag` (false: no spring-arm lag, the miner stays centered; lag speed 0.5 when on), `CameraFieldOfView` (75), `AimRotationInterpSpeed` (0 = instant), `MouseAimPlaneHeight` (0), `StickAimMinInput` (0.1), `DroneClass` (none; set to the drone Blueprint), `DigContactMargin` (10 uu, provisional, task-029-05; replaces `DigReachMargin`), `DigMinMoveInput` (0.1, provisional; below it the input does not steer the dig arc), `StartingWeapons` (array of `ARRWeapon` classes, empty; `BP_Miner`: the burst rifle only since task-024-04), `GuaranteedWeaponClasses` (empty by default: each class spawned after `StartingWeapons` unless an entry of `StartingWeapons` is that class or a subclass), `WeaponCatalogue` (`FRRWeaponCatalogueEntry` list offered by new-weapon cards, [[sys-upgrades]]; native defaults `ARRShotgun`, `ARRTurretLauncher` with provisional French descriptions; `BP_Miner` lists the Blueprints), `MaxWeapons` (4), `WeaponAttachSocketName` (none = attach to the capsule, which turns with the aim yaw), `WeaponAttachOffset` ((0, 20, −40) uu from the capsule center, X forward, Y right; used only when the socket is none). Per-weapon socket (task-400): `AddWeapon` first uses the weapon `HandSocketName` when set and present on the mesh (`SnapToTargetIncludingScale` since [[task-474-miner-scale-down]]: the weapon takes the mesh scale with relative scale 1, which the left-hand IK grip math assumes; `SnapToTargetNotIncludingScale` before; set but missing: warning, then the shared path), else `WeaponAttachSocketName`, else the capsule ([[sys-weapons]]); `BP_Miner` mesh socket `WeaponSocket_R` ([[bp-miner]]). Damage: `IFramesDuration` (0.25 s), `IFramesEffectClass` (`URRGE_IFrames`), `BlinkRate` (12 Hz, full hide/show cycles), `HitShakeClass` (`TSubclassOf<UCameraShakeBase>`, `EditDefaultsOnly`, `BlueprintReadOnly`, category `Miner|Damage`, default `URRHitCameraShake`, none = no shake; task-417-01, provisional owner 2026-11-02). `HandleDamageReceived(Damage, bIsCritical, HealthLeft)`, bound to the health set `OnDamageReceived`, calls `URRCameraShakeLibrary::PlayCameraShake(this, 1.f, HitShakeClass)` when `Damage` > 0 and the class is set (plain call, the miner is the view target), before the i-frames branch so the lethal hit shakes; same strength whatever the damage ([[sys-camera-shake]]). Holds the spawned drone in `Drone` (`GetDrone()`) and the arena grid in `ArenaGrid` (`GetArenaGrid()`). Movement defaults (gravity 1.5, acceleration 1000, no ledge walk-off) are component properties, editable in Blueprint. Shadows (task-263-01): `PostInitializeComponents` calls `RRShadows::DisableCastShadows` (`World/RRShadows.h`): every primitive of the miner (skeletal mesh, Blueprint components) casts no shadow; `ARRWeapon::PostInitializeComponents` does the same for every weapon and turret, `ARRProjectile` for every projectile (only the grid rocks cast, [[lights-no-shadows]]). Blob shadow (task-264-02): `BlobShadow` on the capsule, diameter = capsule radius × `BlobShadowDiameterScale` (`Miner|Blob Shadow`, 2.2), placed 3 uu above the capsule bottom ([[sys-blob-shadow]]).
  - `ARRPlayerController` (`RRPlayerController.h`): editable `DefaultMappingContext`, `MappingContextPriority`, `MoveAction`, `StickAimAction`, `MouseAimAction`, `PlaceTurretAction` (Boolean, bound on Started → `ARRMiner::PlaceTurret`), `PlaceTurretKeys` (E, right mouse button, gamepad face button bottom), `bHideCursorWhileStickAiming`. While `PlaceTurretAction` is unset, a transient action mapped to `PlaceTurretKeys` lives in a transient mapping context added at `MappingContextPriority` + 1, so the button works without assets; once the asset is set its keys come from `DefaultMappingContext`. Cursor shown by default. HUD: editable `HUDWidgetClass` (none; set to the HUD widget Blueprint); `BeginPlay` creates it for a local player only and binds it, `OnPossess` rebinds it to the new miner; `GetHUDWidget()` ([[sys-hud]]).
  - `ARRGameMode : AGameModeBase` (`RRGameMode.h`): default pawn and controller classes set in Blueprint. Game over: `RegisterMiner(ARRMiner*)` (called by the miner `BeginPlay` when the auth game mode is an `ARRGameMode`) binds the miner `OnDeath`; the first death disables the input of every player controller (`DisableInput`), broadcasts `OnGameOver` (BlueprintAssignable) once and arms a timer that reopens the current level (`UGameplayStatics::OpenLevel` on `GetCurrentLevelName`) after editable `RestartDelay` (3 s, miner gdd M1). `IsGameOver()`, `GetRestartDelay()`, `GetRestartTimeRemaining()` (−1 when not armed). `EndPlay` clears the timer.

  - `URRMinerAnimInstance` (`RRMinerAnimInstance.h`, task-401-01, provisional): left hand IK inputs for the ABP_Miner Two Bone IK ([[bp-miner]]). `LeftHandIKTarget` (`FVector`, BlueprintReadOnly, category `RogueRigs|Anim`) = location in cm of the held weapon mesh socket `LeftHandGrip` (public static `LeftHandGripSocketName`) in the bone space of the bone carrying `WeaponSocket_R` (the right hand; socket name read from `ARRWeapon::GetHandSocketName()`), zero when alpha is 0. `LeftHandIKAlpha` (float, BlueprintReadOnly) = 1 only when the hand-held weapon has a mesh with `LeftHandGrip`, else 0. Event driven, never per frame: `NativeBeginPlay` binds `ARRMiner::OnWeaponAdded` and handles weapons already held; `HandleWeaponAdded` calls `RefreshLeftHandIK` (ignores weapons not attached to the miner on their hand socket); `NativeUpdateAnimation` untouched; `NativeUninitializeAnimation` unbinds. Limitation: no weapon-removed event, so removing a hand-held weapon does not reset the alpha. Refresh limit (task-404, Q5 A, no code change): `LeftHandIKTarget` is computed only at weapon add, so a live edit of RifleMesh or of the `LeftHandGrip` socket in PIE is not followed; a value saved in BP_BurstRifle or on SM_BurstRifle is picked up at the next weapon spawn, because the socket moves and scales with RifleMesh ([[bp-burst-rifle]]). A live refresh would be a separate cpp task (Q5 B, not done). `WeaponSocket_R` is not rotated and `ARRMiner::AddWeapon` is unchanged. Upper body source (task-406-01, cpp 49a881c3): `UpperBodySequence` (`TObjectPtr<UAnimSequenceBase>`, `EditDefaultsOnly`, `BlueprintReadOnly`, category `Animation|UpperBody`, default nullptr) is the pose the ABP_Miner Layered blend per bone applies from bone `Spine` up; no C++ logic reads it, only the ABP. Set in the ABP_Miner class defaults (A_Miner_UpperRifle_V2Grip since task-409-03; A_Miner_UpperRifle_V2 from task-408-03); swap it for another weapon pose ([[bp-miner]]). Debug cvars (task-408-01, cpp 4e0cce39; cheat, no gameplay effect): `rr.Debug.MinerAnimFreeze` 1 freezes the miner animation time (mesh `GlobalAnimRateScale` 0, the graph keeps evaluating), 0 restores the previous rate scale; `rr.Debug.MinerUpperPose <name>` loads `/Game/RogueRigs/Characters/Miner/Anims/<name>` into `UpperBodySequence` of the player-controlled miner (`ApplyDebugUpperPose`, reloaded only when the value changes), empty restores the class default, a missing asset logs a warning and keeps the current sequence. The task-407 right arm offsets and `rr.Debug.MinerArmFix` no longer exist; the class holds no right arm offset (until task-410, next paragraph).

  - Right hand offset (task-410-01, cpp 5ca2bac7, provisional, unverified: no PIE run by the crew, the owner checks): `RightHandOffsetLocation` (`FVector`, cm) and `RightHandOffsetRotation` (`FRotator`, deg), `EditDefaultsOnly`, `BlueprintReadOnly`, category `Animation|RightHand`, default 0 (0 = the V2Grip pose unchanged). Frame: the hand socket (`GetHandSocketName()` of the held weapon, else `WeaponSocket_R`): X toward the muzzle, Y side, Z rifle top. Order: turn around the socket point (the grip), then move. The hand moves on a rifle that stays in place (task-411 counter-move, below); task-410 first moved the rifle with the hand. ABP inputs (`BlueprintReadOnly`, same category): `RightHandIKEffector` (`FVector`, RightHand bone space, bone units about x100 scale), `RightHandRotationDelta` (`FRotator`), `RightHandOffsetAlpha` (1 if the offset is non-zero else 0; the two inputs are zero at alpha 0). Math: `D = S.Inverse() * O * S` (S socket transform in RightHand space, O the offset); effector = `D.GetLocation()`, delta = `D.Rotator()`. Computed in `NativeBeginPlay` from the class defaults and on a cvar change only (`ApplyDebugRightHandOffset` in `NativeUpdateAnimation`, player-controlled pawn only, one string compare per frame). Cvar `rr.Debug.RightHandOffset` (FString, cheat): `X Y Z` or `X Y Z Pitch Yaw Roll`, `""` restores the class defaults; a bad value logs the warning `rr.Debug.RightHandOffset: bad value "<v>" (expected ...); offset kept` and changes nothing. Each apply logs (LogRogueRigs) `RightHandOffset <Pawn>: RightHandOffsetLocation=(..) RightHandOffsetRotation=(..) | socket <name> on bone <bone> -> RightHandIKEffector=.. RightHandRotationDelta=.. RightHandOffsetAlpha=<0|1>`; the first two groups are what to type in the ABP_Miner Class Defaults to keep a value ([[bp-miner]]). Reach risk: the arm has a fixed length and the right Two Bone IK has stretching off, so keep offsets to a few cm.

  - Rifle counter-move (task-411-01, cpp 3b80bb41, provisional, unverified: no capture, build OK, no PIE run by the crew; not checked: rifle stays put, left hand on the handguard, restore on uninitialize). With O = `FTransform(RightHandOffsetRotation, RightHandOffsetLocation)` the hand moves by D (above); the weapon parts are counter-moved so the rifle world transform is unchanged: `R' = R * (C * O^-1 * C^-1) = R * O^-1` (C identity, rifle snapped to the socket). Applied to the weapon mesh carrying `LeftHandGrip` (`RifleMesh`) and to `Muzzle` (`M' = M * O^-1`), scale 1.25 kept. The relative transform stays fixed, so animations that move the hand still move the rifle; only the offset does not. R is the Blueprint value saved on first apply in `BlueprintRelativeTransforms` (a `TMap`, not UPROPERTY; the CDO lacks Blueprint components), so no accumulation; offset 0 or a missing socket restores exactly; `NativeUninitializeAnimation` restores and clears. Only the weapon attached on the miner mesh `HandSocketName` (`IsHeldOnHandSocket`), and only components attached directly to the weapon root (others warn and skip). Call order: `RefreshRightHandOffset` sets the ABP inputs and `AppliedHandOffset`, then per weapon `RefreshHeldWeapon` = `ApplyRifleCounterMove` then `RefreshLeftHandIK` (the grip moved in hand space, so the left hand target is refreshed); also from `HandleWeaponAdded` and `NativeBeginPlay` (the old left IK loop there is removed). Protected helpers: `IsHeldOnHandSocket`, `RefreshHeldWeapon`, `ApplyRifleCounterMove`, `GetBlueprintRelativeTransform`, `RestoreCounterMovedComponents`. New public `ARRWeapon::GetMuzzle() const` (not UFUNCTION). The apply log line now ends with ` | counter-move: <weapon> RifleMesh <comp> relative=(...) Muzzle <comp> relative=(...)` or `no hand-held weapon`; the cvar help says the rifle stays in place and follows the hand in animations. Q1 no clamp: past arm reach the hand stops short and the rifle shifts by the missing part. Asset values of RifleMesh and Muzzle stay as saved ([[bp-burst-rifle]]).
