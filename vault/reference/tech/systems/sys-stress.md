# Stress tooling

- responsibility: put many robots in the arena on demand and measure frame time per robot count ([[stress-test-m1]]). Debug only, no gameplay role.
- main_classes: `URRStressSubsystem` (`Source/RogueRigs/Debug/RRStressSubsystem.h/.cpp`, `UTickableWorldSubsystem`, Game and PIE worlds, absent in shipping like `URRCheatSubsystem`); `FRRStressStepResult` (one step: count, frames, avg and p99 frame, game, draw, GPU ms; max frame and game; burst kills, barrels, explosions resolved; blocks destroyed, event frames, flow-field computations; robots alive avg / min / max, spikes and their causes, forced horde size, miner level); `ERRStressMode` (Peace, Fire, Burst, Chain, Dig, Walk, Game). Launcher: `Scripts/Run-StressTest.ps1 [-Counts] [-Settle] [-Measure] [-Mode] [-Class] [-PreExec "cmd,cmd"] [-Trace cpu,frame,bookmark,region] [-TraceFile] [-ExtraArgs] [-Exe]` (Insights trace to `Saved/Traces/`, not committed; [[perf-trace-m1]]). `-Exe <staged>/RogueRigs/Binaries/Win64/RogueRigs.exe` runs the cooked Development game instead of the editor binary (no project path, no `-game`; CSV and log under `<staged>/RogueRigs/Saved/`); staging command in [[build-toolchain]]. Tests: `RogueRigs.Stress.*` ([[sys-automation-tests]]).
- entry_points (console, all `ECVF_Cheat`):
  - `rr.Stress.Spawn <N> [Class]`: N robots on walkable cells reachable in the flow field ([[sys-flow-field]]), nearest first from `rr.Stress.MinCells` (3) BFS steps from the miner, one per free cell (wraps with a quarter-cell corner offset when cells run out), capsule `rr.Stress.FloorClearance` (2 uu) above the floor, ignoring `MaxAlive`. Default class: first `ARRChaser` subclass among the first spawner's classes (`ARREnemySpawner::GetSpawnableClasses`, [[sys-spawner]]); `Class` matches a spawnable class name (substring, case insensitive) or a class path.
  - `rr.Stress.Clear`: destroys the stress robots (no death, no XP).
  - `rr.Stress.Peace <0|1>`: loose `State.Invulnerable` on the miner ASC and `StopFiring` on every weapon (1), reverse (0), so counts hold.
  - `rr.Stress.Run [Counts] [Settle] [Measure] [Quit] [Mode] [Class]`: Mode `peace` (S0, default), `fire` (S2: miner invulnerable by loose tag, every weapon firing, stress robots raised to `rr.Stress.FireHealth` (10⁶) so the count holds), `burst` (S7: each step clears and spawns fresh robots of Class, and on the first frame after the settle time kills them all through `KillEnemy` and destroys every barrel cell, explosions resolved by the queue during the measure window). `rr.Spawner.Enabled 0`, `stat unit` on; per count (separator `,` or `+`; default `rr.Stress.Counts` 50,100,200,300,400) tops the stress robots up, waits `Settle` s (`rr.Stress.SettleSeconds` 5), samples every frame for `Measure` s (`rr.Stress.MeasureSeconds` 20), logs one `Stress step:` line; at the end writes `Saved/Stress/Stress_<time>.csv` and exits when `Quit` is 1. CSV profiler events `Stress_<N>_Settle` / `_Measure` mark the steps; an Insights timing region `Stress_<N>_Measure` (category Stress) spans each measure window, for `-region=` exports.
  - Grid modes (task-023-01): `chain` (peace, robots tough as in fire; first measure frame queues `rr.Stress.ChainCount` (30) explosions of row `rr.Stress.ChainRow` (Barrel), no source object, at seeded block points in the ring `rr.Stress.ChainMinRange`–`ChainMaxRange` (1500–5000 uu) around the miner) and `dig` (same peace and toughness; during the measure window destroys the non-barrel block cells nearest the miner, source Drone, at `rr.Stress.DigRate` (8) cells of `rr.Stress.DigReferenceCellSize` (200 uu) per second, i.e. the same world area per second at any cell size). `walk` (task-029-02; same peace and toughness; during the measure window the miner is teleported along a circle of `rr.Stress.WalkRadius` (800 uu) around its position at `rr.Stress.WalkSpeed` (600 uu/s), skipping targets on non-walkable cells, so the flow-field goal keeps changing cell). Every step also records blocks destroyed, event frames (worst of the two frames after an explosion or a destruction; count, avg, max) and flow-field work (frames with any flow-field work, avg and max flow ms of those frames, [[sys-flow-field]] `GetLastFrameWorkMilliseconds`); extra CSV columns `Blocks,EventFrames,EventAvg,EventMax,FlowComputes,FlowAvg,FlowMax`.
  - Grid granularity (`Debug/RRGridStress.h/.cpp`, namespace `RRGridStress`, commands compiled out of shipping): `rr.Stress.Subdivide <Factor> [NoNav]` splits every cell into Factor × Factor cells of `CellSize / Factor` at runtime (same world size and block area; a spawn or barrel cell keeps one middle sub cell, barrel neighbours become rock), rebuilds instances and forces the flow field; NoNav has no effect since task-029-01 (grid components are never navigation relevant; it was the what-if of [[stress-grid-cells]]). Grid chunking and distance fields can be compared through `-PreExec "set RRArenaGrid ChunkCells <N>,set RRArenaGrid bGridAffectsDistanceFields 1,rr.Stress.Subdivide 3"` (read at the rebuild). `rr.Stress.GridBench [Iterations=20] [Quit] [Delay=3 s]` logs `GridBench:` lines: cell and instance counts, used memory, forced BFS ms, spawner candidate scan ms, line of sight µs per ray (20000 seeded rays 200–2000 uu), component breakdown of a destruction, dig destruction plus rebuild ms, synchronous `DestroyCellsInRadius` at the barrel radius on seeded points; it destroys terrain, so it runs in its own launch. Use with the launcher: `-PreExec "rr.Stress.Subdivide 3"`. Results: [[stress-grid-cells]]. Protected grid and flow-field members are reached through derived access structs (same idiom as `Tests/RRTestAccess.h`); the grid class is unchanged.
  - Real-game mode `game` (task-067-01): counts are spawner `MaxAlive` caps (set through a derived access struct, restored at the end), the timed spawner and wave director stay on, no stress robot, no peace; the pacing bot ([[sys-progression]]) drives the miner with profile `rr.Stress.GameProfile` (3, run-and-collect) and seed `rr.Stress.GameSeed` (1), weapons fire, kills, pickups, damage numbers, HUD and minimap run (each step logs `HUD widgets in viewport`, `minimap texture`). Fill: every `rr.Stress.GameFillInterval` (0.5 s) while under the cap and no horde is active, one director wave of `rr.Stress.GameFillPacks` (2) packs drawn from the current (else next) phase weights through `TrySpawnDirectorWave`. Forced horde: the first pending listed horde is moved to front at `rr.Stress.GameHordeAt` (20 s) into the first measure window, size `rr.Stress.GameHordeMin`–`Max` (40–60), trigger RunTime; until its lull the cap is lowered by the horde max so the front is not shrunk. Use one launch per cap (the director clock restarts).
  - Spikes (every mode): a measured frame over `rr.Stress.SpikeMs` (25) logs `Stress spike:` (t into the measure, frame, game, draw, GPU, last flow ms, robots, blocks, explosions) tagged `fill robots` (game-mode wave of the previous frame), `gc` (post garbage collect delegate) or `after pause` (level-up screen); CSV columns `AliveAvg,AliveMin,AliveMax,Spikes,SpikesFill,SpikesGC,SpikesPause,Horde,Level`.
  - C++: `SpawnStressEnemies`, `ClearStressEnemies`, `GetStressEnemyCount`, `SetPeace`, `SetMinersInvulnerable`, `SetMinerWeaponsFiring`, `StartRun`, `GetResults`, `ResolveEnemyClass`; static `KillEnemy` (self-applied explosion-damage GE far above health: normal death, XP, kamikaze explosion), `DestroyAllBarrels`, `ParseMode`.
  - Visual checks (`Debug/RRVisualCheckCommands.cpp`, `ECVF_Cheat`, compiled out of shipping): `rr.Debug.Shots <Delay> <Count> <Interval> [Prefix]` takes game viewport screenshots (no UI) to `Saved/Screenshots/<platform>/<Prefix>_NN.png` on a real-time ticker and logs the damage number state (pushed, pending, component, live and spawned particles) per shot; `rr.Debug.CritChance <0..1>` sets the CritChance base of every weapon. Use through `-PreExec` with `slomo 0.25` to catch short-lived effects ([[stress-damage-numbers]]). A screenshot frame costs ≈ 0.5 s.
  - While a run is paused (level-up screen from burst XP) the subsystem still ticks, picks card 0 (`RRCheats::ChooseUpgrade`) and skips sampling.
- data: none; tunables are the console variables above.
- depends_on: [[sys-flow-field]], [[sys-grid]], [[sys-spawner]], [[sys-enemies]], [[sys-player]], [[sys-weapons]], [[sys-gas-core]].
- implements: [[stress-test-m1]] method.
- gotchas: samples are the `FStatUnitData` raw values of the game viewport (frame = `FApp::GetDeltaTime`, game, render thread "Draw", GPU 0), refreshed only while `stat unit` is drawn; the overlay stays on during a run. The module does not link RenderCore/RHI, so the engine globals are not read directly. `-csvprofile` / `-csvCaptureFrames` wrote no file from the editor binary `-game` (task-013-01); use Insights for per-system costs (`-Trace`; `-ExtraArgs -statnamedevents` adds engine stat scopes but ≈ +2 ms game thread at 400). Robots converge on the miner: steady state is one dense crowd, the worst case for collision and avoidance. A fresh mass spawn and a step-by-step top-up give different numbers at the same count (±2 ms game thread). Steps of 55 s measure + 5 s settle last ≈ 61 s, the GC interval: the full GC then lands in the top-up gap between measure windows and the max frame misses it; check GC frames in a trace or with `-ExtraArgs '-LogCmds="LogGarbage Log"'` (`GC purged` lines). Burst: barrels exist once per process, so run one count per launch; raise `rr.Stress.MinCells` (8) through `-PreExec` so kamikazes do not arm during the settle time.
