# Stress — run modes

  - `rr.Stress.Run [Counts] [Settle] [Measure] [Quit] [Mode] [Class]`: Mode `peace` (S0, default), `fire` (S2: miner invulnerable by loose tag, every weapon firing, stress robots raised to `rr.Stress.FireHealth` (10⁶) so the count holds), `burst` (S7: each step clears and spawns fresh robots of Class, and on the first frame after the settle time kills them all through `KillEnemy` and destroys every barrel cell, explosions resolved by the queue during the measure window; since task-114-01 `DestroyAllBarrels` lights every barrel fuse (counted, nothing queued) and the barrel explosions come 1.5 s later: a measure window shorter than the fuse sees none). `rr.Spawner.Enabled 0`, `stat unit` on; per count (separator `,` or `+`; default `rr.Stress.Counts` 50,100,200,300,400) tops the stress robots up, waits `Settle` s (`rr.Stress.SettleSeconds` 5), samples every frame for `Measure` s (`rr.Stress.MeasureSeconds` 20), logs one `Stress step:` line; at the end writes `Saved/Stress/Stress_<time>.csv` and exits when `Quit` is 1. CSV profiler events `Stress_<N>_Settle` / `_Measure` mark the steps; an Insights timing region `Stress_<N>_Measure` (category Stress) spans each measure window, for `-region=` exports.
  - Grid modes (task-023-01): `chain` (peace, robots tough as in fire; first measure frame queues `rr.Stress.ChainCount` (30) explosions of row `rr.Stress.ChainRow` (Barrel), no source object, at seeded block points in the ring `rr.Stress.ChainMinRange`–`ChainMaxRange` (1500–5000 uu) around the miner) and `dig` (same peace and toughness; during the measure window destroys the non-barrel block cells nearest the miner, source Drone, at `rr.Stress.DigRate` (8) cells of `rr.Stress.DigReferenceCellSize` (200 uu) per second, i.e. the same world area per second at any cell size). `walk` (task-029-02; same peace and toughness; during the measure window the miner is teleported along a circle of `rr.Stress.WalkRadius` (800 uu) around its position at `rr.Stress.WalkSpeed` (600 uu/s), skipping targets on non-walkable cells, so the flow-field goal keeps changing cell). Every step also records blocks destroyed, event frames (worst of the two frames after an explosion or a destruction; count, avg, max) and flow-field work (frames with any flow-field work, avg and max flow ms of those frames, [[sys-flow-field]] `GetLastFrameWorkMilliseconds`); extra CSV columns `Blocks,EventFrames,EventAvg,EventMax,FlowComputes,FlowAvg,FlowMax`.
  - Grid granularity (`Debug/RRGridStress.h/.cpp`, namespace `RRGridStress`, commands compiled out of shipping): `rr.Stress.Subdivide <Factor> [NoNav]` splits every cell into Factor × Factor cells of `CellSize / Factor` at runtime (same world size and block area; a spawn or barrel cell keeps one middle sub cell, barrel neighbours become rock), rebuilds instances and forces the flow field; NoNav has no effect since task-029-01 (grid components are never navigation relevant; it was the what-if of [[perf-stress-grid-cells]]). Grid chunking and distance fields can be compared through `-PreExec "set RRArenaGrid ChunkCells <N>,set RRArenaGrid bGridAffectsDistanceFields 1,rr.Stress.Subdivide 3"` (read at the rebuild). `rr.Stress.GridBench [Iterations=20] [Quit] [Delay=3 s]` logs `GridBench:` lines: cell and instance counts, used memory, forced BFS ms, spawner candidate scan ms, line of sight µs per ray (20000 seeded rays 200–2000 uu), component breakdown of a destruction, dig destruction plus rebuild ms, synchronous `DestroyCellsInRadius` at the barrel radius on seeded points; it destroys terrain, so it runs in its own launch. Use with the launcher: `-PreExec "rr.Stress.Subdivide 3"`. Results: [[perf-stress-grid-cells]]. Protected grid and flow-field members are reached through derived access structs (same idiom as `Tests/RRTestAccess.h`); the grid class is unchanged.
  - Real-game mode `game` (task-067-01): counts are spawner `MaxAlive` caps (set through a derived access struct, restored at the end), the timed spawner and wave director stay on, no stress robot, no peace; the pacing bot ([[sys-progression]]) drives the miner with profile `rr.Stress.GameProfile` (3, run-and-collect) and seed `rr.Stress.GameSeed` (1), weapons fire, kills, pickups, damage numbers, HUD and minimap run (each step logs `HUD widgets in viewport`, `minimap texture`). Fill: every `rr.Stress.GameFillInterval` (0.5 s) while under the cap and no horde is active, one director wave of `rr.Stress.GameFillPacks` (2) packs drawn from the current (else next) phase weights through `TrySpawnDirectorWave`. Forced horde: the first pending listed horde is moved to front at `rr.Stress.GameHordeAt` (20 s) into the first measure window, size `rr.Stress.GameHordeMin`–`Max` (40–60), trigger RunTime; until its lull the cap is lowered by the horde max so the front is not shrunk. Use one launch per cap (the director clock restarts).
