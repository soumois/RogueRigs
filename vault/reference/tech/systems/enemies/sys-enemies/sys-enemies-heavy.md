# Heavy (`ARRHeavy`)

- responsibility: the heavy's decisions and its ground slam.
- main_classes: `ARRHeavy` (Blueprintable, `RRHeavy.h/.cpp`), `ERRHeavyState` Chase, Telegraph, Slam, Recover, Dead. Capsule 48 × 124 (2× chaser, radius ≤ 80 so it crosses one-cell corridors); the Blueprint mesh carries the 2× look.
- behavior: Chase (flow field, arrival = `AttackRange` × `ArrivalRangeRatio` 0.5 = 180.5 uu) → Telegraph when the miner is within `AttackRange` × `SlamTriggerRatio` (0.7 → 252.7 uu, `IsTargetWithin`) and the cadence allows it (previous slam + 1 / `AttackRate` − `WindUp`): stopped, `OnTelegraphStart`, committed for `WindUp` (1.0 s since task-293-01; 0.6 s from task-032-01; was 0.8) → Slam (one frame): miner within `AttackRange` (361 uu since task-293-01; 289 since task-052-01; 340 after task-039-01, 400 before, 220 before task-028-01; 2D centers) takes `ApplyDamageSpecTo(DamageEffectClass, Damage)` (`URRGE_DamageFlat`, × `AttackPower`); `OnSlam(Location = feet, Radius)` → Recover (stopped) `RecoverDuration` → `OnRecover` → Chase. The shockwave only looks for the miner: no terrain damage ([[destruction-rules]]), no robot damage. Knockback: base `ApplyKnockback` with CSV resistance 0.8 ([[sys-enemies-base]]).
- ground signal (task-115-01, [[ground-telegraph]]): `GroundTelegraph` (`URRGroundTelegraphComponent`, constructor default subobject under the capsule, offset down by the capsule half height = feet). `EnterState(Telegraph)`: `SetRadius(GetSlamRadius())` (= `Stats.AttackRange`, the radius `PerformSlam` tests), Danger, progress 0, `Show`. Each Telegraph step of `UpdateBehavior`: `SetProgress(GetTelegraphProgress())` (1 on the slam frame), no extra tick. Leaving Telegraph (Slam, Dead via `HandleDeath`) hides it; `ARREnemy::HandleDeath` and `OnPoolReleased` also hide it ([[sys-ground-telegraph]]); `ResetForNewLife` sets progress 0, radius, `Hide`. Slam rules unchanged. Far-zone bug (task-119-01): the decal itself was correct; the zone seen on far, chasing heavies was the Blueprint `ShockRing` (its nodes removed from every BP_Heavy event in task-123-01, the component deleted in task-124-02) (slam-radius ring, a static mesh), turned on by the base `SetMeshesVisible(true)` that showed every mesh on a recycling `RelocateTo` and in `HandleDeath`. Fixed in the base (the flash end shows only what it hid) and `ResetStateMachine` now calls `OnRecover` when it leaves Telegraph, Slam or Recover (ring, glow and tilt reset on a relocation). Getter `GetGroundTelegraph`.
- Blueprint-facing: events `OnTelegraphStart`, `OnSlam(Location, Radius)`, `OnRecover` (end of recovery; also on death during Telegraph or Recover, to reset the pose); pure `GetState`, `IsTelegraphing`, `GetTelegraphProgress` (0 → 1 over the telegraph, 0 outside: body tilt and glow), `GetSlamRadius`, `GetTelegraphDuration`, `GetLastSlamTime`, `GetSlamCount`.
- animation (task-284-05 base clip writer, [[sys-enemies-base]]; slam clips task-285-02, baked in task-285-01): `BodyMesh`; Chase: walk loop (clip 0, rows 0..15, random phase), written on the movement change. Telegraph entry (after `EnterState`): `PlayClip(TelegraphClipId 1, WindUp - SlamContactLead)` (rows 16..30, clamped, played by the shader at 30 fps without RunRate: raise over frames 0..13, 0.43 s baked). Stretched raise (task-293-01): each later Telegraph step (`UpdateTelegraphClipFrame`, inside `UpdateBehavior`, no extra tick; only while the clip-1 timer is pending) rewrites the clip start (CPD 1) to now − frame / 30 with frame = `TelegraphRaiseTopFrame` (13) × clamp(`GetTelegraphProgress` × WindUp / (WindUp − SlamContactLead), 0, 1), so the fists reach the top when the slam-down clip starts (BP_Heavy: 0.80 s, 16.25 frames/s; C++ default lead: 0.85 s); one CPD write per frame per telegraphing heavy (cap 5); the shader lerps between rows, so a write every rendered frame shows exactly that frame. Its timer end (`OnAnimClipEnded` override, still Telegraph) plays `SlamClipId` 2 untimed (rows 31..46, looped by the shader, contact at 0.133 s) 0.15 s before the slam, so the fists land on the slam frame; `PerformSlam` plays `RecoverClipId` 3 untimed (rows 47..61, clamped, contact held 3 frames, rest by 0.467 s < `RecoverDuration` 0.5). Clip 3 ends at the rest pose (row 61), so `RestClipId` stays 3 (relocation or other movement-off moments hold it). Recover → Chase: walk loop again. Clip 2 must be replaced before 0.533 s (its loop restart): the slam frame does it 0.15 s in. Death leaves the clip (the override ignores a pending timer once Dead); `ResetStateMachine` → Chase replaces it. `EditDefaultsOnly` (`Heavy|Animation`): `TelegraphClipId` 1, `SlamClipId` 2, `RecoverClipId` 3, `SlamContactLead` 0.15 s (code choice from the 285-01 contact frame), `TelegraphRaiseTopFrame` 13 (task-293-01, top of the raise in clip 1); `BakedClipFrameRate` 30 (constant, the shader's clamped-clip rate).
- entry_points: the getters above, `GetSlamHitCount` (tests).
- data: CSV row `Heavy` ([[sys-enemies]]): AttackRange = slam radius, WindUp = telegraph, AttackRate 0.5 = one slam every 2 s (task-032-01; was 0.4, 2.5 s). `EditDefaultsOnly`: `DamageEffectClass` (`URRGE_DamageFlat`), `SlamTriggerRatio` 0.7, `RecoverDuration` 0.5 s, `TelegraphFlashRate` 0 (no mesh blink: the Blueprint glows); `ArrivalRangeRatio` 0.5. Alive cap 5: spawner entry `MaxAlive` ([[sys-spawner]]).
