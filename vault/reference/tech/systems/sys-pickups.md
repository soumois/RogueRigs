# Pickups

- responsibility: the pickup actor (pop, attraction, collection) and the drop rule of ore and heal ore blocks. XP pickups add XP on collection; Heal pickups apply a heal effect (task-034-01; amount from the ore table since task-088-02, [[heal-ore]]); Ore pickups only log and broadcast.
- main_classes: `ARRPickup` (`Source/RogueRigs/Pickups/RRPickup.h/.cpp`, `Abstract`, Blueprintable), `ERRPickupType` (Ore, Heal, XP), `ERRPickupPhase` (Pop, Rest, Magnet, Collected); `URRPickupSubsystem` (`Pickups/RRPickupSubsystem.h/.cpp`, `UTickableWorldSubsystem`, Game and PIE worlds, pauses with the world) moves every pickup in one loop per frame: player 0 pawn and its `PickupRadius` read once, then `ARRPickup::UpdateMotion` per pickup (actor tick off; on only when the subsystem is missing). No physics, no collision: root `PickupMesh` `NoCollision`, no overlap, no navigation; `BeginPlay` also sets `NoCollision` and `CanCharacterStepUpOn` No on every primitive component, Blueprint ones included (task-028-03: the saved `BP_PickupXP` Trail blocked the miner, which climbed onto cubes and rock). Blueprint subclasses set `PickupType` and the mesh.
- lifecycle (task-027-01, DRGS-like, [[xp-level-up]]): spawned at a cell center (grid) or at robot feet (XP). Pop: random yaw (or `SetPopYaw` before BeginPlay), distance random in [`PopMinDistance`, `PopMaxDistance`]; horizontal ease-out over `PopDuration`; vertical main arc of `PopArcHeight` from spawn Z to spawn Z + `HoverHeight` over the first 1 - `PopBounceFraction` of the pop, then a bounce of `PopBounceHeight`. Rest: `AttractDelay` from the end of the pop, never attracted meanwhile. Magnet: first frame after the rest with the 2D distance to the miner within its `PickupRadius`: latches (keeps flying even if the miner leaves the radius), `OnMagnetStart`, speed starts at `MagnetStartSpeed` and gains `MagnetAcceleration` per second up to `MagnetMaxSpeed` (applied before each step), straight 3D line to the miner; nearby cubes latch together and form a stream. Heal refusal (task-089-01, [[heal-ore]]): `IsRefusedByMiner` is true for a Heal pickup when the miner Health >= MaxHealth; in Rest it is checked after the radius test, so a refused pickup stays at its rest point and latches on the first frame the miner is damaged and in radius (re-checked each frame, no event binding, nothing for XP and ore); in Magnet it is checked at the start of each `FlyToMiner` step: a pickup in flight when the miner reaches full health (another heal collected first, same frame included) goes back to Rest where it is, snapped to its rest Z, `MagnetSpeed` 0, never consumed; no despawn. A partial heal is collected and clamped at MaxHealth by the effect (95 / 100 + 15 = 100). No `OnMagnetStop` event (`BP_PickupHeal` has no trail nor `OnMagnetStart` handler, so nothing stays on). Collect within `CollectDistance` (or when the step reaches it): Verbose log; an XP pickup calls `AddXP(XPAmount)` ([[sys-progression]]); a Heal pickup calls `ApplyHeal`: `HealEffectClass` (`URRGE_Heal` by default) with SetByCaller `Data.Heal` = `HealAmount` applied to the miner ASC, skipped when the amount is 0, the miner is dead or has no ASC ([[sys-gas-core]]); `ARRMiner::NotifyPickupCollected(Type, Location)` broadcasts `OnPickupCollected(Type)` then `OnPickupCollectedAt(Type, Location)`; Blueprint event `OnCollected(Location)`; destroy.
- properties (all `EditDefaultsOnly`, provisional, task-027-01 values): `PickupType` Ore, `OreValue` 1 (task-070-01; set per chunk by the grid from the deposit's `ChunkValue`, [[ore-economy]]; nothing consumes it yet), `XPAmount` 1 (set per cube by the robot), `HealAmount` 0 (C++ default, read only by Heal pickups; `BP_PickupHeal` does not override it; task-088-02: the grid sets it per pickup from the deposit `HealValue`, `OreTypes.csv` row `Heal` = 15, so a 2 × 2 vein restores 60; a heal pickup spawned outside the grid heals nothing), `HealEffectClass` `URRGE_Heal`, `PopMinDistance` 80 uu, `PopMaxDistance` 220 uu, `PopDuration` 0.35 s, `PopArcHeight` 80 uu, `PopBounceHeight` 15 uu, `PopBounceFraction` 0.25, `HoverHeight` 30 uu, `AttractDelay` 1.0 s, `MagnetStartSpeed` 400 uu/s, `MagnetAcceleration` 4000 uu/s2, `MagnetMaxSpeed` 2500 uu/s, `CollectDistance` 50 uu. Measured at 60 fps: arc peak 95 uu, bounce peak 45 uu, rest at 0.350 s; first magnet frame 466.7 uu/s, cap 2500.
- XP drop: `ARREnemy::DropXP` bursts `XPCubeCount` cubes of its `XPPickupClass` at its feet after the death shrink (chaser 3, kamikaze 4, shooter 6, heavy 12, set in each constructor; 0 = one per XP point), each worth `Stats.XPValue / XPCubeCount` so the values add up to the robot XP, spawned deferred with `SetXPAmount` and `SetPopYaw` = random start + index x 360 / N, jittered by a quarter spacing ([[sys-enemies-base]]); tests use the native `ARRTestPickupXP`.
- drop rule (in `ARRArenaGrid`, see [[sys-grid]]): `OrePickupClass` for Ore, `HealPickupClass` for HealOre; other types drop nothing. Per cell the grid counts dig drops already spawned (`CellDigDrops`). After each `ApplyTerrainDamage` that leaves the block standing, crossed = floor((max health − health) / `DropInterval`), capped at the number of multiples strictly below max health; the difference with the count is spawned. The destroying hit spawns no dig drop; `DestroyCell` spawns `DestroyDropCount`, whatever the source. Defaults at 67 uu (task-029-04): ore and heal ore health 1.5 = interval 1.5, so no dig drop and 1 pickup at destruction (one per broken block, [[ore-blocks]]); a heal cluster of 3 × 3 gives 9 (one 200 uu heal block gave 5); since task-034-01 the drone mines the whole vein at once ([[sys-drone]]), so all 9 drop together. The former 4.5 health with 3 at destruction gave drops at 1.5 and 3.0, then 3 (5 total).
- spawn queue (task-070-01, [[ore-in-rock-plan]]): `URRPickupSubsystem` (`Config = Game`) `RequestSpawn(Class, Location, Owner, OreValue, HealAmount = 0)` spawns at once (deferred, `SetOreValue`, and `SetHealAmount` when above 0, before BeginPlay) while fewer than `MaxSpawnsPerFrame` (config, 4) were spawned this frame (frame = one world time value), else appends to a FIFO drained first in `Tick` under the same cap; `GetQueuedSpawnCount`, `SetMaxSpawnsPerFrame`. Every grid drop (ore and heal) uses it; XP bursts and the bonus chest spawn directly. A 2 × 2 heal vein pops its 4 pickups in one frame.
- entry_points: `ARRPickup::GetPickupType`, `GetOreValue`, `SetOreValue`, `GetPhase`, `IsMagnetized`, `GetMagnetSpeed`, `GetXPAmount`, `GetHealAmount` (BlueprintPure), `SetXPAmount`, `SetHealAmount`, `SetPopYaw`, `GetPopStart`, `GetPopEnd`; protected `IsRefusedByMiner`, `ReturnToRest`; Blueprint events `OnMagnetStart()` (trail on) and `OnCollected(Location)` (detached sparkle); `URRPickupSubsystem::GetPickupCount`, `GetMagnetizedCount`, stat `RR Pickups Tick`; `ARRMiner::GetPickupRadius()`, `OnPickupCollected`, `OnPickupCollectedAt` ([[sys-player]]).
- data: `PickupRadius` from `PlayerBaseStats.csv` ([[sys-gas-core]]); drop tunables on the grid Blueprint.
- depends_on: [[sys-grid]], [[sys-player]], [[sys-gas-core]].
- implements: [[ore-blocks]], [[heal-ore]], [[ore-economy]] (drops only), [[player-stats]] (pickup radius).
- gotchas: one subsystem loop and one 2D distance per resting pickup per frame; no pooling (tests count live `ARRPickup` actors). Stress S7 burst of 400 chasers (1200 cubes, task-027-01): avg 9.19 ms, p99 11.34 ms; the single burst frame (400 deaths + 16 barrels) 109 ms max, the known per-death burst cost. Grid ore and heal chunks use the same 80-220 uu pop: at 67 uu cells a chunk can rest over unbroken rock for its 1 s rest (a Blueprint can lower `PopMaxDistance`). A single hit that both crosses a multiple and destroys the block gives no dig drop for that multiple. Fourth test (task-034-01): heal pickups were collected (magnet, event) but healed nothing, there was no heal code; collection itself works for every type, no overlap is involved. Ore value: 1 per chunk (owner 2026-10-10), carried by `OreValue`. The ore chunk Blueprint should have no trail component ([[ore-in-rock-plan]], task-070-02). Pickups spawn only in a game world.
