# HUD

- responsibility: feed the UI layer from C++: the miner's health, XP and level-ups, and the game-over event. Layout, text and visuals live in the Blueprint subclass (BP agent, [[cpp-bp-split]]); no gameplay logic in the widget.
- main_classes: `URRHUDWidget : UUserWidget` (`Source/RogueRigs/UI/RRHUDWidget.h`, `Abstract`). `BlueprintImplementableEvent`s to implement in the Blueprint subclass: `OnHealthChanged(float Current, float Max)` (Health and MaxHealth of the miner), `OnXPChanged(float Current, float Needed, int32 Level)` and `OnLevelUp(int32 NewLevel)` (miner progression, [[sys-progression]]; drives the "LEVEL UP" text), `OnUpgradeOfferShown(TArray<FRRUpgradeCard> Cards, bool bCanReroll)` (show or refresh the card screen: opening, after a reroll, each chained screen; game paused, cursor shown) and `OnUpgradeOfferClosed()` (hide it, game resumes) ([[sys-level-up]]), and `OnGameOver()`. Run flow ([[sys-objectives]]): `OnAlertChanged(float Alert, bool bPaused)` (0..1; paused while the console is pending), `OnObjectiveChanged(bool bActive, ERRConsoleState State, int32 MarkedRocksLeft, int32 MarkedRocksTotal)` (bActive false = no console yet; the text lives in the Blueprint), `OnObjectiveProgressChanged(float Progress, bool bHacking)`, `OnExtractionReady()`, `OnShuttleCountdown(float Remaining, FVector ShuttleLocation)` (every countdown frame), `OnRunEnded(bool bSuccess)` (true = success screen, false = run-lost screen; game paused, Game and UI input, cursor shown, any card screen already closed; since task-206-03 not sent on a level 1-3 extraction of a run, which opens the intermission instead, and true on level 4 = run won, `URRRunTransitionSubsystem::IsRunWon`; intermission and loading screens are separate widgets, not HUD panels: [[sys-run-transition]]). Turret ([[sys-turret]]): `OnTurretChargesChanged(int32 Charges, int32 MaxCharges, float RechargeDuration)` (0 = no recharge running; not called without a launcher) and pure `GetTurretRechargeProgress()` (0..1, per-frame bar). Pressure ([[sys-hud-pressure]]): `OnPlayerDamaged`, `OnHordeIncoming`, `OnAlertEventsChanged`. Bonus chest icon (task-056-01, [[objective-bonus-chest]]): `ERRAlertBarEventType::BonusChest` (appended, value 3), listed second (console, chest, hordes, shuttle) while `BonusChestAlertThreshold` > 0, `Position` = that threshold (0.6), `Index` -1, `bDone` once `GetBonusChest()` is complete; the locator ignores the chest. Guards: `OnHealthChanged` is never called with Max <= 0 and `OnXPChanged` never with Needed <= 0, so the Blueprint may divide by them.
- Weapon slots (task-037-01, [[readability-rules]] ammo HUD; pure, call each frame): `GetWeaponSlotCount()` = bound miner `MaxWeapons` (0 unbound); `GetWeaponSlots()` (that many entries) or `GetWeaponSlot(Index)` fill `FRRWeaponSlotHUD` {`bOwned`, `Weapon`, `bIsTurretLauncher`, `Rounds`, `MagazineSize`, `bReloading`, `ReloadProgress`, `Charges`, `MaxCharges`, `bRecharging`, `RechargeProgress`}. Slot order = valid `GetWeapons` in acquisition order (slot 0 = rifle); later slots locked (`bOwned` false, defaults). Turret launcher: `Charges`/`MaxCharges` (also in `Rounds`/`MagazineSize`), `RechargeProgress` 0..1 of the one charge recharging, `bReloading` false. Others: `Ammo`/`MagazineSize` rounded down, reload from [[sys-auto-fire]] (progress 0 when it never ends).
- Blueprint calls (buttons): `ChooseUpgrade(int32 Index)` (0-based in `Cards`; bool), `RequestReroll()` (bool), `CanRerollUpgrade()` (pure); forwarded to the bound miner's `URRLevelUpComponent`. `RestartLevel()` (both end screens) forwards to `URRRunFlowSubsystem::RestartLevel` (resets the run, reopens the map at level 1). Card fields: `DisplayName`, `TargetText`, `ValueText`, `Tier` ([[sys-upgrades]]).
- entry_points: Bind calls in [[sys-hud-bindings]].
- widget lookup after the split (task-094-10): WBP_HUD holds only the seven panels ([[wbp-hud]]), so `GetWidgetFromName` on the HUD finds none of their widgets. `FindHUDWidget(FName)` (and static `FindWidgetInTree(const UUserWidget* Root, FName)` for tests and debug) searches the HUD tree, then depth first the tree of every nested `UUserWidget` (panels inside panels too); null for an unknown name or None; a panel never searches its parent. `FindUserWidgetWithProperty(Root, Name)` returns the widget whose class has a Blueprint variable Name (HitFlash is in WBP_HealthStatus). Every name lookup of C++, debug commands and tests uses them (WarmUpVignette, LogVignetteState, the integration tests). Test `RogueRigs.HUD.FindWidgetInPanels`.
- NativeTick (task-103-01): no override any more; the root does no per-frame work. The vignette floor became a one-shot `WarmUpVignette` ([[sys-hud-pressure]]); the minimap and locator follow the miner's and its camera's `TransformUpdated` and send `OnMinimapViewChanged` / `OnLocatorViewChanged` ([[sys-hud-minimap]], [[sys-hud-events]]). Per-frame values left in the HUD: reload and turret recharge progress (read by their panels while they run), the vignette fade while it runs and the locator arrow pulse (Blueprint visuals). `NativeOnInitialized` / `NativeConstruct` hand the root to every panel (`URRHUDPanelWidget::BindToHUD`), warm the vignette, create the minimap, bind `FViewport::ViewportResizedEvent`.
- legacy display events (task-094-10 decision): WBP_HUD implements none of the `BlueprintImplementableEvent`s above (the panels bind [[sys-hud-events]] directly); calling an unimplemented one is a no-op. They and their bindings are kept, not removed: the events are part of the documented HUD API, `GetMinimapTexture`/`GetMinimapState` are read by WBP_MinimapLocator (the BlueprintImplementableEvent `OnMinimapTextureReady` became a delegate in task-103-01), and tests drive `ChooseUpgrade` / `RequestReroll` (no longer called by WBP_UpgradeChoice). The `BlueprintNativeEvent`s `OnPlayerDamaged`, `OnHordeIncoming`, `OnAlertEventsChanged` are overridden by the test HUD (`URRTestHUDWidget`), so they stay.
- data: editable on the controller Blueprint: `HUDWidgetClass` (category HUD, none by default; set to the HUD widget Blueprint).
- depends_on: [[sys-player]] (miner, controller, game mode), [[sys-gas-core]] (health attribute set), [[sys-progression]]; module `UMG`.
- implements: [[miner]] (M1 "Game Over" text, health display data), [[xp-level-up]] (XP bar and level-up data).
- gotchas: the game mode exists only on the server, so the game-over binding is single-player only. If the controller begins play before the miner applied its CSV base stats, MaxHealth is 0: the bind-time push is skipped (it caused a divide-by-zero in WBP_HUD at PIE start) and the base-stat change fires `OnHealthChanged` with the real values. The XP curve is loaded at component initialization, so the bind-time `OnXPChanged` has its need.
