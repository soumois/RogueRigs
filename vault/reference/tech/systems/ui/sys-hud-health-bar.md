# HUD health bar

- responsibility: drive the health bar and text of the health status panel from the miner health events (task-203-01); the shown fill glides to the real health both ways; an off-white damage chunk behind it keeps the lost health visible for a moment, then shrinks to the shown fill (task-203-02); on each hit the fill flashes towards white and fades back in about 0.1 s (task-203-03). Vignette and GAME OVER stay in the Blueprint ([[wbp-health-status]]); the hit flash is distinct from the screen damage vignette, which is unchanged.
- main_classes: `URRHealthStatusWidget : URRHUDPanelWidget` (`Source/RogueRigs/UI/RRHealthStatusWidget.h`, Abstract), future parent of WBP_HealthStatus (reparent: task-203-07). `BindWidgetOptional` `HealthBar` (UProgressBar), `DamageChunkBar` (UProgressBar, drawn behind `HealthBar`; added to WBP_HealthStatus by task-203-07) and `HealthText` (UTextBlock): the class works on a Blueprint lacking them. Pure `GetShownFraction`, `GetTargetFraction`, `GetChunkFraction`, `GetFlashAlpha`, `GetCurrentFillColor`; `IsBarUpdateRunning` (C++, tests).
- entry_points: native bind `NativeBindToMiner` (new virtual of `URRHUDPanelWidget`, run by `SetMiner` just before the `BindToMiner` hook): removes its handlers from the previous miner, adds them (`AddUniqueDynamic`) to `OnHealthChanged` and `OnDamaged`, shows `GetCurrentHealth` / `GetMaxHealth` snapped (null miner: "0 / 0", fraction 0). A separate native step, not `BindToMiner_Implementation`, because a Blueprint override of the hook replaces the native implementation, so the vignette and game-over graphs keep running without a parent call. `NativeConstruct` rebinds (the Blueprint Destruct unbinds every listener of the miner) and draws.
- rules: text = "round(Current) / round(Max)" at once on each `OnHealthChanged`. Target = Current / Max clamped 0..1 (0 when Max <= 0). Shown += (Target - Shown) * min(1, DrainRate * dt), snapped when the gap is under `DrainSnapThreshold`. Fill colour = `GetCurrentFillColor()` = lerp(`GetBaseFillColor()` (`FillColor`), `FlashColor`, Flash). Hit flash: on each `OnDamaged` Flash = `FlashStrength` and the bar is drawn at once (full flash on the hit frame); each frame Flash -= `FlashDecay` * dt, floor 0 (linear, 1/9 = 0.11 s). Bind or no-world snap sets Flash = 0. Damage chunk: on each `OnDamaged` (broadcast after `OnHealthChanged`, so the chunk still holds the fraction shown before the hit) `ChunkDelayRemaining` = `ChunkDelay` (a new hit restarts it); the chunk holds while it counts down, then Chunk += (Shown - Chunk) * min(1, ChunkRate * dt), snapped under `DrainSnapThreshold`. After every step Chunk = max(Chunk, Shown): never below the shown fill, a heal past it pulls it up. Bind or no-world snap also sets Chunk = Shown, delay 0. Chunk bar: percent = Chunk, fill colour = `ChunkColor`.
- per-frame update: no tick. A health event arms `UpdateBarEffects` with `SetTimerForNextTick` (dt = world delta seconds); it re-arms each frame until `AreBarEffectsSettled`, then stops (settled = Shown == Target, Chunk == Shown, no chunk delay left and Flash == 0). Extension points for task-203-04 to 06: state in the class, start in `HandleDamaged` / `HandleHealthChanged`, step in `AdvanceBarEffects`, settle test in `AreBarEffectsSettled`, drawing in `ApplyBarVisuals`, colour in `GetBaseFillColor` (the flash lerps from it, so task-203-06 turning it into a gradient keeps the flash).
- data: `EditDefaultsOnly` on the Blueprint subclass, provisional (owner 2026-10-16, reference video): `DrainRate` 10 per s, `DrainSnapThreshold` 0.001, `FillColor` (0.9, 0.05, 0.05, 1), `ChunkDelay` 0.4 s, `ChunkRate` 7 per s, `ChunkColor` #fff0e0 sRGB (`FLinearColor(FColor(0xFF, 0xF0, 0xE0))`, converted to linear; red #f25a5a and pink #ff99cc tried in the video, rejected), `FlashColor` white (1, 1, 1, 1), `FlashStrength` 1, `FlashDecay` 9 per s.
- depends_on: [[sys-hud-events]] (panel base, miner events), [[sys-player]] (miner).
- implements: [[task-203-health-bar-juice]] (health bar juice, no gdd node).
- gotchas: world timers do not run while the game is paused, so a change during the card screen glides after it closes. Until task-203-07 removes them, the Blueprint ShowHealth also writes the bar percent and text (also bound to OnHealthChanged), which would override the drain. Not seen on screen. The chunk only shows if `HealthBar`'s background is transparent where it is empty (Blueprint style, task-203-07); not checked on screen. The flash is not checked on screen either. No automated test covers the widget yet.
