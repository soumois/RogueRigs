# Pickups — xp

- XP drop: `ARREnemy::DropXP` bursts `XPCubeCount` cubes of its `XPPickupClass` at its feet after the death shrink (chaser 3, kamikaze 4, shooter 6, heavy 12, set in each constructor; 0 = one per XP point), each worth `Stats.XPValue / XPCubeCount` so the values add up to the robot XP, requested through `URRPickupSubsystem::RequestXPCube(Class, Location, XPAmount, PopYaw)` (direct deferred spawn only without the subsystem), `PopYaw` = random start + index x 360 / N, jittered by a quarter spacing ([[sys-enemies-base]]); tests use the native `ARRTestPickupXP`.
- big XP block (task-110-01, [[xp-level-up]], provisional): when the requested cube class default has `XPBigPickupClass` (`EditDefaultsOnly` `TSubclassOf<ARRPickup>` on `ARRPickup`, category Pickup|XP, default null = feature off), `RequestXPCube` returns null and stores the request; `FlushXPCubes` (start of the subsystem `Tick`, after the actor ticks where robots die, so per frame; tests call it) groups requests per small class and per square cell of `XPMergeBucketSize` (floor(X / size), floor(Y / size)); a bucket with more than `XPMergeThreshold` cubes turns each full group of `XPMergeGroupSize` (request order) into one `XPBigPickupClass` pickup at the group's mean location, first cube's pop yaw, `XPAmount` = float sum of the group; the remainder stays small (20 = 2 big + 4 small; 8 or fewer unchanged). The big block is acquired from the pool like a cube (same `SpawnMaxFrames`, reset hooks, root template scale, magnet, radius and collect rules). Tunables `Config = Game` on the subsystem, section `[/Script/RogueRigs.RRPickupSubsystem]` of `Config/DefaultGame.ini`: `XPMergeBucketSize` 200 uu, `XPMergeThreshold` 8, `XPMergeGroupSize` 8 (C++ defaults, no ini line yet). Enable: set `XPBigPickupClass` = `BP_PickupXPBig` in the class defaults of `BP_PickupXP` (task-110-02); the big Blueprint sets `PickupType` XP, its own mesh, a size 1.53 times the cube (was 1.8 until task-196-01; root template scale stays the pool's restore reference) and colour ([[color-code]]); leave its own `XPBigPickupClass` empty. Counter `GetTotalXPBigBlocksRequested`, `GetPendingXPCubeCount`. While the world is paused the flush waits for the next tick.
- pool (task-092-01, replaces the task-070-01 4-per-frame queue, [[sys-actor-pool]]): `RequestSpawn(Class, Location, Owner, OreValue, HealAmount = 0)` (grid ore and heal) and `RequestXPCube` acquire from `URRActorPoolSubsystem` with `MaxFrames` = `SpawnMaxFrames` (`Config = Game`, 3; 0 = `AcquireImmediate`, used by tests reading drops in the same frame): an idle pickup is reused at once, missing ones are created within 3 frames (ceil(pending / 3) per frame). Requester = the subsystem, so a drop outlives the dying robot. Values are set by the pool `OnInit` (before BeginPlay on creation, before `OnPoolAcquired` on reuse). Returns the pickup when delivered now, else null. `GetQueuedSpawnCount` (pending creations), `GetPoolStats` (pool counters summed over the pickup classes requested), `GetTotalXPCubesRequested` (stress tag). Reset (`IRRPoolable`): `OnPoolReleased` unregisters, `DeactivateImmediate` on every FX component (`BP_PickupXP` `TrailFX`), clears phase, magnet latch and speed, pop timers, target miner, pop yaw, and puts `XPAmount`, `OreValue`, `HealAmount` back to the class defaults (a heal request with 0 keeps the default, as a fresh spawn); `OnPoolAcquired` starts a new life (`StartLife`: pop from the new location, register; guarded by `bLifeStarted` so a fresh actor started in BeginPlay is not started twice) and re-activates auto-activate FX. The pool resets the rotation (`BP_PickupXP` faces the miner on magnet start). No Blueprint change needed. The heal refusal needs no reset (re-checked each frame). Pooled idle pickups are unregistered (`GetPickupCount` skips them); every `TActorIterator<ARRPickup>` (pacing bot, grid stress, tests) skips `IsPooledIdle`. The bonus chest still spawns its chunks directly (destroyed on collection).
- scale pop (task-309-01, bonus chest chips only): `FRRPickupScalePop` (StartScale, PeakScale, Duration, PeakTimeFraction; Duration 0 = off; `Evaluate(t)` ease-out to the peak at PeakTimeFraction x Duration, ease-in-out back to 1) passed as the optional last argument of `RequestXPCube` (kept in the pending request; a merged big block gets none) or `ARRPickup::SetSpawnScalePop` before the life starts. It starts at the first `UpdateMotion` (not in `StartLife`, so the pool reads the true root template scale after a fresh spawn) from the current root scale, writes base x factor, ends at exactly 1; `OnPoolReleased` restores the base and clears it. Getters `GetSpawnScaleFactor`, `IsSpawnScalePopActive`. Values from [[sys-objectives-console-chest]].
