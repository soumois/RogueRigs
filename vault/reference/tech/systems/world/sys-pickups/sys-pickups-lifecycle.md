# Pickups — lifecycle

- lifecycle (task-027-01, DRGS-like, [[xp-level-up]]): spawned at a cell center (grid) or at robot feet (XP). Pop: random yaw (or `SetPopYaw` before BeginPlay), distance random in [`PopMinDistance`, `PopMaxDistance`]; horizontal ease-out over `PopDuration`; vertical main arc of `PopArcHeight` from spawn Z to spawn Z + `HoverHeight` over the first 1 - `PopBounceFraction` of the pop, then a bounce of `PopBounceHeight`. Rest: `AttractDelay` from the end of the pop, never attracted meanwhile. Magnet: first frame after the rest with the 2D distance to the miner within its `PickupRadius`: latches (keeps flying even if the miner leaves the radius), `OnMagnetStart`, speed starts at `MagnetStartSpeed` and gains `MagnetAcceleration` per second up to `MagnetMaxSpeed` (applied before each step), straight 3D line to the miner; nearby cubes latch together and form a stream. Heal refusal (task-089-01, [[heal-ore]]): `IsRefusedByMiner` is true for a Heal pickup when the miner Health >= MaxHealth; in Rest it is checked after the radius test, so a refused pickup stays at its rest point and latches on the first frame the miner is damaged and in radius (re-checked each frame, no event binding, nothing for XP and ore); in Magnet it is checked at the start of each `FlyToMiner` step: a pickup in flight when the miner reaches full health (another heal collected first, same frame included) goes back to Rest where it is, snapped to its rest Z, `MagnetSpeed` 0, never consumed; no despawn. A partial heal is collected and clamped at MaxHealth by the effect (95 / 100 + 15 = 100). No `OnMagnetStop` event (`BP_PickupHeal` has no trail nor `OnMagnetStart` handler, so nothing stays on). Collect within `CollectDistance` (or when the step reaches it): Verbose log; an XP pickup calls `AddXP(XPAmount)` ([[sys-progression]]); a Heal pickup calls `ApplyHeal`: `HealEffectClass` (`URRGE_Heal` by default) with SetByCaller `Data.Heal` = `HealAmount` applied to the miner ASC, skipped when the amount is 0, the miner is dead or has no ASC ([[sys-gas-core]]); `ARRMiner::NotifyPickupCollected(Type, Location)` broadcasts `OnPickupCollected(Type)` then `OnPickupCollectedAt(Type, Location)`; Blueprint event `OnCollected(Location)`; released to the actor pool when a pool member, else destroyed (task-092-01).
- properties (all `EditDefaultsOnly`, provisional, task-027-01 values): `PickupType` Ore, `OreValue` 1 (task-070-01; set per chunk by the grid from the deposit's `ChunkValue`, [[ore-economy]]; nothing consumes it yet), `XPAmount` 1 (set per cube by the robot), `HealAmount` 0 (C++ default, read only by Heal pickups; `BP_PickupHeal` does not override it; task-088-02: the grid sets it per pickup from the deposit `HealValue`, `OreTypes.csv` row `Heal` = 15, so a 2 × 2 vein restores 60; a heal pickup spawned outside the grid heals nothing), `HealEffectClass` `URRGE_Heal`, `PopMinDistance` 80 uu, `PopMaxDistance` 220 uu, `PopDuration` 0.35 s, `PopArcHeight` 80 uu, `PopBounceHeight` 15 uu, `PopBounceFraction` 0.25, `HoverHeight` 30 uu, `AttractDelay` 1.0 s, `MagnetStartSpeed` 400 uu/s, `MagnetAcceleration` 4000 uu/s2, `MagnetMaxSpeed` 2500 uu/s, `CollectDistance` 50 uu. Measured at 60 fps: arc peak 95 uu, bounce peak 45 uu, rest at 0.350 s; first magnet frame 466.7 uu/s, cap 2500.
- glow fade (task-148-01, provisional, owner 2026-10-13): `bGlowFade` (default false), `GlowFadeDuration` 0.2 s, `GlowFadeDataIndex` 0 (all `EditDefaultsOnly`, category `Pickup|Glow`). For a pickup with `bGlowFade`, a fade value 0..1 (`GlowFade`) moves toward a target (`GlowFadeTarget`) at 1 / `GlowFadeDuration` per second (0 s = instant) and is written with `UPrimitiveComponent::SetCustomPrimitiveDataFloat(GlowFadeDataIndex, value)` on `PickupMesh` each time it changes (no dynamic material instance). Target: 0 during Pop, 1 at the start of Rest (landing, also `ReturnToRest`), 0 at the start of Magnet and at Collected (the pickup is released the same frame, so the Magnet fade-out is what shows). Updated at the top of `ARRPickup::UpdateMotion`, i.e. in the existing `URRPickupSubsystem` loop (or the fallback tick), only while the value differs from the target (one frame after the phase change; no new tick, no timer). Reset: `ResetGlowFade` in `StartLife` (fresh spawn and pool reuse) and `OnPoolReleased` sets value and target to 0 and writes 0, so a fresh or pooled pickup never shows the material default nor flashes. `bGlowFade` false (ore, heal, C++ default): no write, no behaviour change. The material side (scalar parameter with Use Custom Primitive Data at index 0) and `bGlowFade` true on `BP_PickupXP` / `BP_PickupXPBig` come with task-148-02.
