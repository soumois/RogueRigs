# Grid — barrels

- barrels: a barrel cell keeps its block HISM instance and has two healths: dig health (`BarrelHealth`, drone) and shot health (`BarrelShotHealth`, projectiles via `ApplyShotDamage`; other block types ignore shot damage). Shot health 0 destroys the cell (source Shot). Barrel fuse (task-114-01, owner 2026-10-12, [[barrel]]): during play, `DestroyCell` on a barrel, whatever brought it to 0 (Shot, Drone, Barrel or Kamikaze explosion), lights its fuse instead of breaking it and returns true: fuse shake started (below), both healths 0, start time kept in `BarrelFuses` (cell → start time, queued flag, telegraph); the cell, its mesh and collision stay. During the fuse every damage is ignored (`ApplyShotDamage`, `ApplyTerrainDamage`, `DestroyCell` return false). The grid ticks while a barrel fuses; when `BarrelFuseSeconds` (1.5, `EditAnywhere`, 0 = old instant behaviour) have elapsed it queues `URRExplosionSubsystem::QueueExplosion(cell center, BarrelExplosionRow, grid as instigator, GetBarrelSource(Cell))`; that explosion destroys the barrel cell itself (inside its own radius, the terrain breaks at the explosion, not at 0 health) without queuing again. If the queue refuses it, the cell is destroyed at once. A chain of two barrels therefore takes 2 × 1.5 s (measured 3.0 s). Outside a game world a barrel is destroyed at once. Queries: `GetBarrelFuseSeconds`, `IsBarrelFusing`, `GetBarrelFuseProgress`, `GetFusingBarrelCount`, `GetBarrelTelegraph`, `GetBarrelTelegraphPoolSize`, `GetBarrelFuseCustomDataIndex`.
- fuse instability (task-197-01, render only; game rules above unchanged): a fusing barrel stays in the dig shake set (render instance only, collision at rest) with amplitudes lerp(start, end, progress ^ `BarrelFuseShakeExponent`) instead of the dig values: horizontal `BarrelFuseShakeStartAmplitude` 2 → `BarrelFuseShakeEndAmplitude` 12 cm, vertical `BarrelFuseShakeVerticalStartAmplitude` 1 → `BarrelFuseShakeVerticalEndAmplitude` 5 cm, exponent 2, frequency `ShakeFrequency` (all `EditAnywhere`, provisional, owner 2026-10-16). `SetCellShaking(Cell, false)` is ignored while it fuses (the drone cannot stop it); the shake stops when the fuse ends. Each grid tick writes the fuse progress (0..1, 1 on the frame the explosion is queued) into per-instance custom data float `BarrelFuseCustomDataIndex` (4: after marked 0 and ore colour 1..3; the barrel HISM gets index + 1 floats at build; a warning is logged if it overlaps) of the barrel render instance, for the body blink material (task-197-03); 0 at fuse start and end; a destroyed barrel's instance is removed and a rebuild creates fresh instances at 0.
- explosion spread (task-121-01): explosions call `QueueDestroyCellsInRadius` (same cells as `DestroyCellsInRadius`, which stays synchronous for direct callers). Barrels in the radius are handled at once (fuse lit, or the exploding barrel's own cell broken), so chain timing is unchanged; the other blocks join a FIFO queue, nearest to the centre first (ties row-major), destroyed with their drops and `OnCellDestroyed` under `CellDestructionBudgetMs` (2 ms, `EditAnywhere`, 0 = all at once) of game-thread time per frame, shared by every call in the frame (`GFrameCounter`), at least one block per frame; the first slice runs in the explosion frame, the rest in the grid tick (enabled while blocks are queued). A queued cell stays a block for every reader (flow field, drone, console marks) until its frame; one destroyed meanwhile is skipped. Queue dropped on rebuild and in `EndPlay`. Black crater on the explosion frame (task-202-01, frames `barrelfx2_09`, `barrelfx3_09`, `barrelfx4_11`): the floor slabs added under the broken blocks were missing for that frame (void seen through, slab sides of the neighbour cells visible at the crater edge), because the floor HISM proxy keeps its creation-time instance count until the async tree build recreates it; fixed in `AddCellInstance` ([[sys-grid]], destruction), verified grey on the explosion frame (`barrelfx5_11`); budget and order unchanged. Queries: `GetPendingCellDestructionCount`, `GetCellDestructionBudgetMs` / `SetCellDestructionBudgetMs`.
- barrel telegraph host: barrels are cells, not actors, so the grid hosts the [[sys-ground-telegraph]] decals: one `URRGroundTelegraphComponent` per fusing barrel, created on demand (`NewObject`, attached to the root, `SetKeepDecalsOffOwner(false)` so the floor and rocks keep receiving it, registered), kept in `BarrelTelegraphs` and reused from `FreeBarrelTelegraphs`, so the count is the peak of simultaneous fuses (a long chain reuses one). In a rendering game world one hidden telegraph is created at `BeginPlay` (`CreateBarrelTelegraph`, task-201-01) so its material is warmed up before the first fuse ([[sys-ground-telegraph]], decal warm-up); headless tests keep creating it on demand. Shown at 0 health at the cell centre on the floor top, radius = the `BarrelExplosionRow` radius (700), Danger, progress = elapsed / fuse each grid tick (1 on the frame the explosion is queued); hidden and released when the cell is destroyed (its explosion) or on rebuild. Source object: one `URRBarrelSource` per barrel cell, created on first request, owned by the grid (`BarrelSources` map, Transient, reset on rebuild), so it is unique, stable and alive for the world; the subsystem lets it explode once.
