# Run transition — next level preload (task-318-01)

- responsibility: from the cards screen opening (`NextLevel`, levels 1-3), prepare the next level in the background so `Continue` starts it without a blocking map load ([[intermission]]).
- approach (choice and reason): rebuild in the same world, no `OpenLevel`. All run levels share L_ArenaM1 and differ only by the grid layout ([[sys-run-layout]]), so a second world is not needed; a background map load is not possible for the map already loaded (same package), and travelling earlier would only move the 2.3-3.3 s blocking load to the stats screen. Keeping the world also keeps the actor pool warm (no new prewarm) and keeps the miner itself as the carried state (cards, weapons, level, XP, health identical by construction; ore stays in the bank).
- main_classes: `URRRunTransitionSubsystem` (`Run/`), steps `ERRNextLevelPrepStep` (None, WaitingForLayout, ClearingLevel, RebuildingTerrain, PlacingMiner, Ready). Resets added: `URRRunFlowSubsystem::ResetForNextLevel`, `ARREnemySpawner::ResetForNextLevel`, `ARRArenaGrid::RebuildForRunLevel`, `URRFlowFieldSubsystem::RebuildForNewTerrain`, `URRExplosionSubsystem::ClearForNextLevel`, `URRRunSubsystem::ConsumeSnapshotInPlace`, `URRRunLogSubsystem::HandleLevelStartedInPlace`, `URRLevelUpComponent::ResumeChoices`; `ARRPlayerController::HandleNextLevelReady` recreates the HUD widget.
- entry_points (sequence; one step per frame on the core ticker, the world stays paused):
  1. WaitingForLayout until the layout requested at the extraction is built (failed: error, grid falls back to its own layout).
  2. ClearingLevel: run flow reset (task-388-01: first `ARRBonusChest::ClearOpeningEffects()` on the live chest, log `URRRunFlowSubsystem: chest effects cleared for the next level: N (chest opened|not opened|none)`; then console, chest, shuttle destroyed; alert, kills, objective flags, carried ore); drone dig released; every `ARREnemy`, `ARRPickup`, `ARRProjectile`, `ARRExplosionFX`, `ARRTurret` back to the pool (pool members) or destroyed; explosion queue and spent sources cleared; then (task-389-01) `URRNiagaraPoolSubsystem::ClearForNextLevel()` right after `URRExplosionSubsystem::ClearForNextLevel` (robot death effects, below); spawner clock, director and hordes reset.
  3. RebuildingTerrain: grid rebuilt from the prepared layout.
  4. PlacingMiner: miner (and drone) teleported to the game mode's player start, flow field recomputed.
  5. Ready: `OnNextLevelReady(LevelIndex, LayoutName)`; the controller replaces the HUD by a fresh one (collapsed until `OnLevelReady`).
  - `Continue`: shop closed, phase Loading, stage PreparingLevel; ready: fade out then `StartPreparedLevel`; else `OnLoadingStarted` and `StartPreparedLevel` when the preparation ends; fade in after it (task-318-02, [[sys-run-transition-fade]]). `StartPreparedLevel`: snapshot consumed in place (log line compares miner and snapshot values), run log level start, level-up choices allowed again, unpause, game input, phase None, `OnLevelReady`.
  - Arrival extractor out of sight (task-397-01, 6de46eec): the arrival extractor placed by `PlaceMinerAtStart` (step 4) is hidden at once (`URRRunFlowSubsystem::SetArrivalShuttleHidden`), because the paused level is still drawn behind the cards and upgrade screens; `StartPreparedLevel` shows it under black right before `OnLevelReady` and the fade in, so its takeoff starts visible only when the fade in finishes. Cause, log lines and verification: [[sys-objectives-run-flow]]. Map-travel fallback untouched.
  - Pure (Blueprint): `IsNextLevelReady()`, `GetNextLevelProgress()` (0-1: completed work steps / 4), `GetNextLevelPrepStep()`.
- data: none.
- depends_on: [[sys-run-layout]], [[sys-grid]], [[sys-objectives-run-flow]], [[sys-spawner-pool-prewarm]], [[sys-hud-bindings]], [[sys-run-log]].
- implements: [[intermission]].
- gotchas: fallback to the map travel of [[sys-run-transition]] when the preparation cannot start (no world, grid or miner). Restart and death still reopen the map and reset to level 1. Differences with the travel path: turret launcher charges and active timed gameplay effects of the miner are kept; Blueprint level actors do not rerun BeginPlay. Each step is one synchronous frame: the terrain rebuild takes about 0.5 s in one frame, so the cards screen freezes for that frame (candidate for time-slicing). No automation test (owner rule). Verified by a -game -nullrhi log (task-318-01, Saved/Logs/task318_game.log): level 2 preparation started on Stats.Next, cleared 0.2 ms, terrain arena_l2 240 x 240 rebuilt in 534 ms, miner placed and flow field 2.2 ms, ready after 539 ms, 3.45 s before Continue; Continue to level ready 0.7 ms, snapshot values equal to the miner values. Level 3 with Continue pressed in the same frame as Stats.Next: ready after 497 ms, level started 504 ms after Continue. Restart and death paths unchanged, not exercised by that run. Chest effects (task-388-01, owner request: the bonus chest glow stayed on in the next level): `StartPreparedLevel` (same world) and `FinishLoading` (map-travel fallback) log `level N start (same world | new world, map travel): bonus chest opening effects alive M` (`ARRBonusChest::CountLiveOpeningEffects`). Verified by a -game run log: 1 removed at the clear, 0 alive at the level 2 start. Not verified: the map-travel fallback after a chest opening (not forced). The look is left to the owner (no capture, owner decision). Cause and API in [[sys-objectives-console-chest]]. Robot death effects (task-389-01, owner request: robot particles stayed in the next level): they froze with the paused world at the extraction and resumed in level 2 (same world); task-388 had covered only the chest. Cause: pooled `NS_RobotDeathPuff`, `NS_HeavyDeathPuff`, `NS_ChaserV2Debris`, `NS_HeavyDebris` (via `URRNiagaraPoolSubsystem`) and `NS_ShieldDebris` (spawned by BP_ShieldChaser(V2) OnShieldBroken through SpawnSystemAtLocation, component owned by the world settings in 5.8). Fix: `ClearForNextLevel()` stops in-use pooled components with DeactivateImmediate, cancels pending starts, returns them to the free list, and stops the tracked world effects (unpooled destroyed, manual-release returned to the engine pool); it returns the count. Log at the clear: `URRNiagaraPoolSubsystem: robot death effects still alive removed for the next level: 55 [NS_RobotDeathPuff 40, NS_ChaserV2Debris 1, NS_HeavyDeathPuff 5, world-owned 9 (NS_ShieldDebris, ...)]`; at the start (`StartPreparedLevel`, and `FinishLoading` on the map-travel path): `URRRunTransitionSubsystem: level 2 start (same world): robot death effects alive 0.` (`CountLiveEffects()`). Verified by -game runs; the look is unverified (owner tests). Shield chaser tracking in [[sys-enemies]]. Rendered -game (task-318-04, Saved/PreloadNextLevel/): cards screen on black drawn in frame 870 while level 2 was preparing (started frame 869, ready 601.8 ms later in frame 872, 3386.5 ms before Continue); level 2 and 3 HUD after the switch show the carried state (Lv 1, 100 / 100, burst rifle, 0 ore), log snapshot values equal to the miner values.
