# Objectives — console chest

  - `ARRConsole` (Blueprintable, not abstract): marks every block of `MarkedCellTypes` (Rock, Ore, HealOre, SpecialOre; barrels excluded; ore table deposits included since task-120-01) whose cell center lies within `ZoneRadiusCells` of the zone centre (the footprint centre, where the actor stands: `MinCell + (Size - 1) / 2` on X and Y: the anchor cell centre for the 3 × 3 console footprint, anchor + 0.5 cell for the 2 × 2 chest; Euclidean) through `ARRArenaGrid::SetCellMarked` ([[sys-grid]]); there is no separate mark radius (`MarkRadiusCells` removed by task-120-01, objective-console 2026-10-13: the marking radius equals the zone radius, so the zone holds no unmarked rock). `FindMarkableCells(Grid, Anchor)` (also used on the class default object by the drop picker) returns nothing when `MarkedCellTypes` is empty. Drop range (task-304-01, [[objective-console]] 2026-10-23): `MinMarkedCells` 10, `MaxMarkedCells` 40 (EditDefaultsOnly, getters `GetMinMarkedCells` / `GetMaxMarkedCells`; `UsesMarkedCellRange` = `MarkedCellTypes` not empty); the picker keeps the candidates whose `FindMarkableCells` count is in range, else the candidates with the smallest gap to it plus a Warning log (max below min counts as min). States `ERRConsoleState`: Locked (marked rocks left, polled each tick), Idle, Hacking, Complete (final). Miner alive within `ZoneRadiusCells` 7 (469 uu on the 67 uu grid; 9 before task-120-01; 2D, from the actor): `ARRDrone::StartHack`; while linked progress += dt / `HackDuration` 10 (12 before task-305-01, 16 before task-120-01, 20 before task-042-01); otherwise `StopHack` and drain `DrainPerSecond` 0.05/s. Mesh: NoCollision by default.
  - `ARRBonusChest : ARRConsole` (task-056-01, Blueprintable, not abstract, [[objective-bonus-chest]]): same hack code, defaults `HackDuration` 8, `ZoneRadiusCells` 6, `DrainPerSecond` 0.05 (inherited), empty `MarkedCellTypes` (no marked rocks: starts Idle), footprint 2 × 2 (set explicitly in its constructor since task-311-01, the console default being 3 × 3). Dropped once per level, after `CheckExtraction`, when the alert reaches `BonusChestAlertThreshold` and extraction is not ready (a cheat jump to full skips it only when extraction becomes ready in that tick); never pauses the bar; spot picked by the console picker (`FindObjectiveCell`) 30–45 cells away, no marked-block range (`UsesMarkedCellRange` false, and the chest call passes `bApplyMarkedRange` false), retried each tick. On `CompleteHack` (or `ForceComplete`) the opening sequence starts (below) and the reward comes once, at the lid opening (`LidOpenDelay` 0.5 s later, task-309-01): `XPNeedFraction` 0 × current level need as XP, `AddXP` skipped at 0 (owner 2026-10-23: one upgrade, not two; was 50 % of the level need, task-307-01; `OnRewardGranted` still passes the XP, now 0; header comment keeps the history), `OreChunkCount` 5 pickups of `OrePickupClass` (none = grid `GetDropPickupClass(Ore)`) popped around it, evenly spread yaw, the XP burst (`SpawnXPBurst(ChipScalePop)`: 3 chips of 8, below) and `URRLevelUpComponent::QueueBonusChoice(BonusLuck` 3) (offer level 0, owner luck + 3 for that offer and its reroll; same delay and pause as a level-up choice). All EditDefaultsOnly.
  - Hack XP burst (task-303-01, [[objective-console]] owner 2026-10-23, provisional; all EditDefaultsOnly, category Console|Reward): at the end of `ARRConsole::CompleteHack` (also via `ForceComplete`) when `bXPBurstOnComplete` (true; `ARRBonusChest` sets false and bursts at its lid opening, task-309-01) `SpawnXPBurst(ScalePop` = none) requests `XPBurstChipCount` 3 chips of `XPBurstChipClass` (TSoftClassPtr, default BP_PickupXPBig, loaded on use; None = no burst, Warning log) worth `XPBurstChipXP` 8 raw XP each (XPGain applies on collection) through `URRPickupSubsystem::RequestXPCube` (pooled; direct deferred spawn without the subsystem; BP_PickupXPBig has no big class so no merge), yaws 360 / count apart from a random start. Each chip starts `XPBurstSpawnRadius` 140 uu from the centre along its yaw (implementation choice: the 3 x 3 mesh at scale 1.361 is about 201 x 172 uu, half diagonal about 132 uu, and the mesh has no collision) and pops outward along the same yaw with the BP_PickupXPBig floaty pop (80-300 uu, 250 uu high, 1.6 s, [[bp-pickup-xp]] floaty_pop), so it rests 220-440 uu from the centre (zone radius 469). The chest keeps `XPBurstChipCount` 3 and `XPBurstChipXP` 8 (task-309 Q7) with `XPBurstSpawnRadius` 80 (implementation choice: the 130 x 70 uu body, half diagonal about 74 uu) and gives each chip `ChipScalePop` (0, 1.3, 0.25 s, peak at 0.6 of the time; [[sys-pickups-xp]] scale pop); the console chips have no scale pop (task-309-01; was `XPBurstChipCount` 0 on the chest, task-303-01). Count kept in `XPBurstChipsSpawned` (getter `GetXPBurstChipsSpawned`; also `GetXPBurstChipCount`, `GetXPBurstChipXP`, `GetXPBurstSpawnRadius`). Then the Blueprint event `OnHackCompleteBurst(FVector Location, int32 ChipCount)` fires once (after `OnHackStateChanged(Complete)`; Location = actor location, floor at the footprint centre; ChipCount 0 on the chest, which fires it at the completion, before its lid opening): BP_ObjectiveConsole spawns its one-shot NS_ConsoleHackComplete there (task-303-02, [[bp-objective-console]]). Just before that event, `CompleteHack` plays `CompleteSoundEvent` (EditDefaultsOnly, category Console|Audio, default `ObjectiveComplete`, None = silent) once at the actor location, console and chest alike (the chest at its completion, before the lid), faded by distance ([[sys-audio-distance-sounds]], task-527). Test `RogueRigs.Console.HackXPBurst` ([[sys-automation-tests]]; since task-309-01 it also checks the chest: nothing before the 0.5 s lid delay, then 3 chips of 8 with a running scale pop that ends at factor 1, no direct XP, one choice, lid 100 and latch 90 at rest, time dilation unchanged).
  - Data socket (task-313-01, owner decision 13 2026-10-24, provisional; implementation choice: offset constant in Mesh space, SM_ConsoleBase has no socket and assets are not edited): `GetHackDataSocket(OutLocation, OutFacing)` = `DataSocketOffset` (12.5, 30, 46) and `DataSocketFacing` (0, 1, 0, horizontal part) through the Mesh transform, so the 1.361 scale of BP_ObjectiveConsole gives about (17, 41, 63) uu from the actor, on the screen face (world +Y at rotation 0). Values from the console_c2 cut report (Blender frame, screen face toward -Y) and the front render with Y negated: the FBX import mirrors Y and keeps X (task-313-02 capture: screen face toward world +Y, screen on the +X side of the mast as in the owner turnaround, so not a 180° turn); first values (12.5, -30, 46) / (0, -1, 0) put the drone at the back panel. Not measured on the mesh. `bHackAtDataSocket` (EditDefaultsOnly, category Console|Hack) is set in the `ARRConsole` constructor to `!IsA<ARRBonusChest>()`: the chest returns false and keeps the default drone hover (chest files untouched). The drone side is in [[sys-drone]].
  - State visuals (task-302-01, [[objective-console]] owner 2026-10-23, provisional, all EditDefaultsOnly in category Console|Visuals): `bDriveStateVisuals` true (`ARRBonusChest` sets it false and drives its lock light instead, below). `FRRConsoleStateVisual` (LampColor, AntennaBlinkRate Hz, ScreenColor, HeadYawSpeed deg/s) per state: `LockedVisual` red (1, 0.05, 0.03), 2, black, 0; `IdleVisual` orange (1, 0.45, 0.05), 2, black, 10; `HackingVisual` green (0.1, 1, 0.15), 2, green (0.1, 1, 0.15), 45; `CompleteVisual` green, 0, green, 0; getter `GetStateVisual(State)`. `AntennaBlinkAmount` 1 (BlinkAmount written while the rate is above 0, else 0; implementation choice). Names: `AntennaHeadName` AntennaHead (the Blueprint StaticMeshComponent, found by name into `AntennaHeadComp`, getter `GetAntennaHead`; a C++ property named AntennaHead clashed with the Blueprint component, compile error and no head found, fixed in task-302-01), slots `AntennaLampSlotName` AntennaOrange (on the head), `OtherLampSlotName` OtherOrange and `ScreenSlotName` Screen (on Mesh). Hook: `SetupStateVisuals` (once, from the first `ApplyStateVisuals`) creates dynamic instances of those slots (a missing slot or head is skipped); `ApplyStateVisuals` runs in `BeginPlay`, in `InitializeConsole` and in `SetConsoleState` on every change, before `OnHackStateChanged`: LampColor on both lamps, BlinkRate and BlinkAmount on the antenna lamp only (0 on the other orange), ScreenColor on the screen. `Tick` turns the head about its local Z by HeadYawSpeed x dt only while that speed is above 0 (also before init and after Complete). Not verified on screen (no capture in task-302-01).
  - Chest lock light (task-308-02, [[objective-bonus-chest]] owner 2026-10-23, provisional; EditDefaultsOnly, category Bonus Chest|Lock Light): `ApplyStateVisuals` is virtual and `SetProgress` calls the new virtual `ApplyProgressVisuals` (no-op on the console). `ARRBonusChest` finds the Blueprint component `LatchComponentName` Latch, makes a dynamic instance of slot `LockLightSlotName` LockLight (MI_ChestLockLight, M_ConsoleLamp parameters LampColor, BlinkRate, BlinkAmount; skipped when missing, as headless) and writes on change only: Idle and Locked `LockIdleColor` (1, 0.05, 0.03) at `LockIdleBlinkRate` 2 Hz; Hacking (drone linked) `LockHackColor` (1, 0.45, 0.05) at `GetHackingBlinkRate(Progress)`, refreshed on each progress change; Complete `LockCompleteColor` (0.1, 1, 0.15), rate 0; BlinkAmount `LockBlinkAmount` 1 while the rate is above 0, else 0. Rate: `LockHackBlinkRateSteps` 2, 3, 4, 6 Hz by equal progress bands (floor(progress x 4), last band includes 100 %); empty list = linear `LockHackBlinkRateStart` 2 to `LockHackBlinkRateEnd` 6. Steps, not linear (implementation choice from the material graph, not a capture): the lamp blinks on Sine(Time x BlinkRate), so a rate change shifts the phase by Time x delta rate; per-frame linear changes would strobe, each step jumps once. Getters `GetLockLightColor`, `GetLockLightBlinkRate`. Not verified on screen.
  - Chest opening (task-309-01, [[objective-bonus-chest]] owner 2026-10-23 provisional; EditDefaultsOnly, category Bonus Chest|Opening; chest tick from the completion, no time dilation): Blueprint components found by name `LidComponentName` Lid and `LatchComponentName` Latch (closed relative rotations kept at the completion; none headless: timeline, events and reward still run). Latch relative Roll = `LatchRollSign` -1 x angle, 0 to `LatchOpenAngle` 90 over `LatchSwingDuration` 0.2 s (ease-out, `LatchEaseExponent` 2). At `LidOpenDelay` 0.5 s, `OpenLid`: `InnerLight` (C++ `UPointLightComponent` under Mesh, relative (0, 0, 30), hidden, no shadow; colour, intensity, radius in Blueprint, intensity read at BeginPlay) shown, scalar `InteriorGlowParameterName` InteriorGlow = `InteriorGlowOnValue` 1 on a dynamic instance of the Mesh slot `InteriorSlotName` Interior (kept on), `OnLidOpened(Location)`, then `GrantReward` (`OnRewardGranted`). Lid relative Roll = `LidRollSign` -1 x angle: to `LidPeakAngle` 115 over `LidRiseDuration` 0.4 s (ease-out, `LidRiseEaseExponent` 2), held `LidHoldDuration` 0.06 s (`OnLidSlam(Location)` at its start; at its end `URRCameraShakeLibrary::PlayCameraShake(LidSlamShakeScale` 1, `LidSlamShakeClass` None = chest preset, [[sys-camera-shake]])), to `LidOpenAngle` 100 over `LidSettleDuration` 0.15 s (ease-in-out), then stays. Light: `InnerLightOnDuration` 3 s then a linear fade over `InnerLightFadeDuration` 0.5 s (implementation choice), hidden. Roll signs from the task-309-07 cut report (Y mirrored by the import; derived, not measured; task-309-05 checks). Then the tick turns off. Getters `IsOpening`, `IsLidOpened`, `GetOpeningElapsed`, `GetLidAngle`, `GetLatchAngle`, `GetLidAngleAt(t)`, `GetLatchAngleAt(t)`, `GetLidOpenDelay`, `GetLidRiseDuration`, `GetInnerLight`, `GetChipScalePop`. Not seen on screen (capture task-309-06).
  - Zone visual (task-113-01, rendering only, rules unchanged): `ARRConsole::GroundTelegraph` (`URRGroundTelegraphComponent`, created in the constructor under `ConsoleRoot`, getter `GetGroundTelegraph`; inherited by `ARRBonusChest` and both Blueprints, [[sys-ground-telegraph]]). `InitializeConsole` sets `SetRadius(GetZoneRadius())` (`ZoneRadiusCells` × grid cell size: console 7 × 67 = 469 uu, chest 6 × 67 = 402 uu), the mode and progress, then `Show()`. Mode: `ZoneBlocked` while marked rocks remain, `ZoneActive` when none (chest: at once); refreshed on every marked-rock count change. Progress = `HackProgress` on every `SetProgress` (rise and drain: the circle shrinks out of the zone). `Hide()` in `CompleteHack` and `EndPlay`. Old diffuse circle, Blueprint-only (REMOVED by task-113-02, 2026-10-13: both HackRing components and both SetRelativeScale3D calls are gone, the GlowAmount calls stay; MI_GroundRingTeal and MI_GroundRingGold are left in place, unreferenced). It was: in `BP_ObjectiveConsole` the `HackRing` component (engine Plane, `MI_GroundRingTeal`) and the `SetRelativeScale3D(HackRing)` call in its `OnHackProgress` graph; in `BP_BonusChest` the `HackRing` component (Plane, `MI_GroundRingGold`) and the same `SetRelativeScale3D` call in its `OnHackProgress` (the `GlowAmount` mesh glow calls stay). Checked in the assets on 2026-10-12.
  - Landing clearance (task-026-00, `RRLandingFootprint`): `ARRConsole::FootprintCells` 3 × 3 (task-311-01, owner 2026-10-24 provisional, was 2 × 2; console mesh scale to follow), `ARRBonusChest` 2 × 2, and `ARRShuttle::FootprintCells` 4 × 3 (cells of 67 uu, EditDefaultsOnly; meshes 100 × 100 and 240 × 160 uu), rotation zero, X along the grid X axis. The footprint spans `Anchor - (Size - 1) / 2` to `+ Size - 1` per axis; the actor stands at its centre (a cell corner for an even size, the anchor cell centre for an odd size); `GetCell` is the anchor. A spot is valid only when every footprint cell is Floor reachable in the flow field. Fallbacks, each logged as a warning: console, no fitting spot in the ring → any ring cell (mesh may overlap blocks); shuttle, no fitting spot in the 37–50 band → the fitting spot nearest to the band, then the reachable floor cell nearest to it (footprint ignored).
  - Opening effects left in the world (task-388-01, gotcha): `BP_BonusChest` spawns `NS_BonusChestOpen` (`OnLidOpened`) and `NS_HeavySlamImpact` (`OnLidSlam`) with `SpawnSystemAtLocation`, so they are owned by the world and survive the chest destroy; the world is paused behind the cards screen, so they resumed in the next level. `NS_BonusChestOpen` never completes (still active 13.5 s after the spawn); `InnerLight` is a chest component and dies with the chest. `OnLidSlam` spawned 0 world effects in the runs (not investigated). C++: `OpenLid` and the slam snapshot every `UFXSystemComponent` of the world with its active state before and after the Blueprint event (`CollectWorldEffects`, `TrackEffectsSpawnedSince`; task-526-01: a component new since the snapshot counts even when not active yet, a known one only when it turned active, i.e. a reused pooled one; the old active-only snapshot missed the first `NS_BonusChestOpen` of a PIE session, whose activation Niagara deferred while the system compiled, so it stayed into the next level), tag the new ones `OpeningEffectTag` (`RRBonusChestOpeningEffect`) and keep them weak in `OpeningEffects` (`GetTrackedOpeningEffectCount`); a log line gives the count per event. `ClearOpeningEffects()` (public; returns how many were alive: effects alive per `IsOpeningEffectAlive` = active, or a Niagara component still waiting to activate (tick on, not complete), plus `InnerLight` when visible) calls `Deactivate` (cancels a waiting Niagara activation) then `DeactivateImmediate` on each, then releases a manual-release pooled Niagara component to its pool or destroys a non-pooled one (auto-release pooled ones return on their own), and hides `InnerLight`; `EndPlay` calls it. `URRRunFlowSubsystem::ResetForNextLevel` calls it before destroying the chest ([[sys-run-transition-preload]], ClearingLevel). Static `CountLiveOpeningEffects(World)` = tagged effects alive + visible chest `InnerLight`s, logged at each level start. Verified by a -game run log (removed 1, 0 alive at level 2 start); task-526-02 capture: level 2 shows no chest light, the deferred-activation case itself not reproduced in -game.
