# Objectives — run flow

  - `URRRunFlowSubsystem` (tickable world subsystem, Game/PIE, not ticked while paused): `AlertSeconds` += dt × cheat multiplier; kills add `KillAlertSeconds` (`NotifyEnemyKilled`, called by `ARREnemy::HandleDeath`; a self-instigated death such as the kamikaze fuse is ignored). Since task-454-01 (e04554fb, owner 2026-11-05, provisional, [[level-flow]] M1) a kill is always counted (`KillCount`, threat) but adds alert only when `DoKillsAddAlert()` (BlueprintPure) is true: horde 0 of the registered spawner is `Done` (its front finished spawning); before that the bar follows time alone and the horde icons stay still. No spawner, director off or no horde, or `bKillsWaitForFirstHorde` false = kills add alert from the start. Nothing grows while the console is pending. At `ConsoleAlertThreshold` the alert is clamped and the console drops on a random Floor cell, straight-line 36–60 cells (67 uu) from the miner's cell, reachable in the flow field, whose whole landing footprint is reachable floor (below), keeping only cells whose zone holds the console class marked-block range ([[sys-objectives-console-chest]], task-304-01; switch `bPreferCellsWithMarkedRocks`, name kept, was a plain has-rocks preference). Alert 1 and nothing pending: `OnExtractionReady` once (phase `ExtractionReady`), then the shuttle lands (below). Run end (`EndRun`, from the shuttle): refused if already ended or the miner is dead (game over owns it); cancels the miner level-up offer (`URRLevelUpComponent::CancelChoices`: screen closed, later screens blocked; the end screen wins, [[sys-level-up]]); player 0 controller `SetPause(true)`, input Game and UI, cursor shown; `OnRunEnded(bSuccess)` once (phase `Ended`). On success, right after the pause (task-370-01, 2e1bde02): `Miner->HideForExtraction()` (miner and drone hidden, no collision) and `Shuttle->StartTakeoff()` (helicopter takeoff ticking while paused, [[sys-objectives-shuttle]]); the screen timing is unchanged. Run levels (task-206-03, [[sys-run-transition]]): a success on levels 1-3 of a run goes to `URRRunTransitionSubsystem::HandleLevelExtracted` (snapshot, advance, intermission) and `OnRunEnded` is NOT broadcast (no success end screen; phase still `Ended`); level 4 success and every loss broadcast it as before. `RestartLevel` calls `URRRunSubsystem::ResetRun`, then reopens the current map (level 1). `ReturnToMainMenu()` (BlueprintCallable, bool, task-390-01, 75dcf06b; the run won end screen "Main Menu" button, [[wbp-alert-objectives]]): `ResetRun` (level 1 next, secured ore 0), then `OpenLevel(URRRunSettings::MainMenuMapName)` directly (no loading screen, no fade; the menu controller sets its own UI input and cursor, [[sys-main-menu]]); false with a warning and nothing reset without a world or with an empty map name; log `URRRunFlowSubsystem: run won: back to the main menu, opening <map>.`. Debug: `rr.Run.MainMenu` ([[sys-cheats]]). During a transition loading the flow is held with `SetRunFlowEnabled(false)` until the pool prewarm is done (no alert, no console).
  - Arrival extractor (task-371-01, 66b2c5e2, be525566): `PlaceArrivalShuttle()` spawns `Config.ShuttleClass` (none = native) and calls `InitializeArrival`. It is stored in its own `ArrivalShuttle` (`GetArrivalShuttle()`), not the exit shuttle: locator, minimap, HUD, drone and `EndRun` ignore it. Start cell = cell under the miner; direction = `ARRMiner::GetScreenUpDirection()` snapped to a grid axis; the footprint (16 x 12 since task-375-01, [[sys-objectives-shuttle]]) starts `ArrivalDistanceCells` from the start cell, centred across (nearest footprint row is the next row, no empty row at 1). Blocks under the footprint and its margin are destroyed when `bArrivalClearsFootprint` is on (task-372, task-376-01). `PlaceMinerAtStart` ends with `PlaceArrivalShuttle`, so it exists under black before the fade in; `ResetForNextLevel` destroys it; `Deinitialize` removes the fade binding. `TickArrival` runs before `TickRunFlow`. Trigger: transition phase not None or fade FadingIn -> takeoff starts in `OnScreenFadeFinished(FadingIn)`; otherwise on the first run flow tick (level 1 from the menu, direct start, restart). Takeoff: [[sys-objectives-shuttle]]. Log lines (LogRogueRigs): `URRRunFlowSubsystem: arrival extractor <Name> placed on (ax, ay), footprint W x H from (minx, miny), start cell (sx, sy), screen up (dx, dy), N block cells under it, frame F; takeoff waits for the fade in|when the level plays.` and `... arrival extractor <Name> takeoff started on (ax, ay) (trigger: fade in finished|level start), frame F; world playing|paused, controls free|held, miner <location>.` Verified: build, -game log with `rr.Run.NextLevel` (takeoff in the fade-in-finished frame), direct level 1, tests Extraction.* and RunFlow.* 9/9. Not verified: map-travel fallback path.
  - Arrival hidden during the intermission (task-397-01, 6de46eec; owner saw the next level's arrival extractor, `BP_ExtractionShuttle_C_2`, at the same cell (128, 120) as the level 1 arrival while the exit shuttle was gone after about 3.6 s). Cause: `PlaceMinerAtStart` places the next level's arrival during the cards screen, when the paused level is still drawn behind the intermission screens, so it was in camera view and not hidden. Fix: public `bool SetArrivalShuttleHidden(bool bHidden, const TCHAR* Reason)` (`SetActorHiddenInGame` on the arrival; false when there is none; log `URRRunFlowSubsystem: arrival extractor <Name> hidden|shown at <loc> (<reason>), frame F.`). `PlaceMinerAtStart` hides it right after `PlaceArrivalShuttle`; `StartPreparedLevel` shows it before `OnLevelReady` and the fade in (screen black then, [[sys-run-transition-preload]]). No new tunable; takeoff values unchanged; map-travel fallback untouched. Verified by -game logs with `rr.Debug.WatchExtractors` ([[sys-cheats]]): before, arrival C_2 `hidden no ... in view -> VISIBLE` every second from phase Shop to FadingOut; after, `hidden yes ... not visible`, then `shown ... frame 3202`, the same frame as the fade in start; takeoff started when the fade in finished, removed after 3.02 s. Tests RogueRigs.RunFlow and Extraction pass 10/10. Out of scope: the miner is still shown at the start spot during the cards screen (`ShowAfterExtraction` in `PlaceMinerAtStart`), possibly task-398.
  - `ArrivalDistanceCells` (`FRRRunFlowConfig`, int32, default 1, ClampMin 1, provisional, owner "1 cell"): read as the nearest footprint row being the next row; 2 would mean one empty cell: to confirm with the owner.
  - Run end listeners (task-211-01): `OnRunEnded` silences the subtitles for the rest of the world ([[sys-subtitles]]) and makes the HUD call `ShowEndScreen` (`URRHUDWidget::OnEndScreenShownDelegate` / `OnEndScreenShown`, the event the bp widgets bind to hide every HUD element but the end screen, [[sys-hud]]); the miner death does the same through `ARRGameMode::OnGameOver`.
  - `FRRRunFlowConfig` (`RRRunFlowConfig.h`): `AlertFillSeconds` 240, `KillAlertSeconds` 0.5, `bKillsWaitForFirstHorde` true (task-454-01), `ConsoleAlertThreshold` 0.4, `ConsoleMinDistanceCells` 36, `ConsoleMaxDistanceCells` 60 (task-029-04: 12–20 cells of 200 uu × 3), `bPreferCellsWithMarkedRocks` true, `ConsoleClass` (none = native `ARRConsole`); extraction ([[extraction]]): `ShuttleMinDistanceCells` 37 and `ShuttleMaxDistanceCells` 50 (task-049-01; was at least 75, no maximum; a max below the min counts as the min), `ShuttleCountdownSeconds` 45, (`ShuttleBoardRadiusCells` removed by task-377-01, ee1a7db8: the level ends on the `BoardZone` box of `ARRShuttle`, [[sys-objectives-shuttle]]; owner 2026-10-30, provisional), `ShuttleClass` (none = native `ARRShuttle`; the BP agent sets the shuttle Blueprint); bonus chest (task-056-01): `BonusChestAlertThreshold` 0.6 (0 = no chest), `BonusChestMinDistanceCells` 30, `BonusChestMaxDistanceCells` 45, `BonusChestClass` (none = native `ARRBonusChest`). Edited on `BP_RRGameMode` (`ARRGameMode::RunFlowConfig`), read on the first tick; `SetConfig` overrides (tests).
  - Clear rect (task-376-01, 9f2c53ae): private `GetClearRect(MinCell, Size, Margin, OutMinCell, OutSize)` grows the footprint by `ARRShuttle::ClearMarginCells` (2, [[sys-objectives-shuttle]]) on each side, clamps it to [0, GridSize-1], minimum size 1; `PlaceArrivalShuttle` (gated by the switch below) and `LandShuttle` pass that rect to `ClearExtractorFootprint` (20 x 16 cells with the defaults; log contexts unchanged, [[sys-grid-api]]). Landing cell order is in [[sys-objectives-shuttle]]. Margin provisional, owner 2026-10-29 ([[task-376-extractor-rock-margin]]).
- arrival footprint switch (task-372-01, de889932, 0e85c9a0): `SetArrivalClearsFootprint(bool)` / `DoesArrivalClearFootprint()` on `URRRunFlowSubsystem`, default on; off, `PlaceArrivalShuttle` still places the extractor but the blocks stay. The extraction landing clear is not affected. Details: [[sys-objectives-shuttle]].
