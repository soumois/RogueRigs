# Objectives — run flow

  - `URRRunFlowSubsystem` (tickable world subsystem, Game/PIE, not ticked while paused): `AlertSeconds` += dt × cheat multiplier; kills add `KillAlertSeconds` (`NotifyEnemyKilled`, called by `ARREnemy::HandleDeath`; a self-instigated death such as the kamikaze fuse is ignored). Nothing grows while the console is pending. At `ConsoleAlertThreshold` the alert is clamped and the console drops on a random Floor cell, straight-line 36–60 cells (67 uu) from the miner's cell, reachable in the flow field, whose whole landing footprint is reachable floor (below), keeping only cells whose zone holds the console class marked-block range ([[sys-objectives-console-chest]], task-304-01; switch `bPreferCellsWithMarkedRocks`, name kept, was a plain has-rocks preference). Alert 1 and nothing pending: `OnExtractionReady` once (phase `ExtractionReady`), then the shuttle lands (below). Run end (`EndRun`, from the shuttle): refused if already ended or the miner is dead (game over owns it); cancels the miner level-up offer (`URRLevelUpComponent::CancelChoices`: screen closed, later screens blocked; the end screen wins, [[sys-level-up]]); player 0 controller `SetPause(true)`, input Game and UI, cursor shown; `OnRunEnded(bSuccess)` once (phase `Ended`). On success, right after the pause (task-370-01, 2e1bde02): `Miner->HideForExtraction()` (miner and drone hidden, no collision) and `Shuttle->StartTakeoff()` (helicopter takeoff ticking while paused, [[sys-objectives-shuttle]]); the screen timing is unchanged. Run levels (task-206-03, [[sys-run-transition]]): a success on levels 1-3 of a run goes to `URRRunTransitionSubsystem::HandleLevelExtracted` (snapshot, advance, intermission) and `OnRunEnded` is NOT broadcast (no success end screen; phase still `Ended`); level 4 success and every loss broadcast it as before. `RestartLevel` calls `URRRunSubsystem::ResetRun`, then reopens the current map (level 1). During a transition loading the flow is held with `SetRunFlowEnabled(false)` until the pool prewarm is done (no alert, no console).
  - Arrival extractor (task-371-01, 66b2c5e2, be525566): `PlaceArrivalShuttle()` spawns `Config.ShuttleClass` (none = native) and calls `InitializeArrival`. It is stored in its own `ArrivalShuttle` (`GetArrivalShuttle()`), not the exit shuttle: locator, minimap, HUD, drone and `EndRun` ignore it. Start cell = cell under the miner; direction = `ARRMiner::GetScreenUpDirection()` snapped to a grid axis; the footprint (16 x 12 since task-375-01, [[sys-objectives-shuttle]]) starts `ArrivalDistanceCells` from the start cell, centred across (nearest footprint row is the next row, no empty row at 1). Blocks under the footprint are counted and logged, not cleared (task-372). `PlaceMinerAtStart` ends with `PlaceArrivalShuttle`, so it exists under black before the fade in; `ResetForNextLevel` destroys it; `Deinitialize` removes the fade binding. `TickArrival` runs before `TickRunFlow`. Trigger: transition phase not None or fade FadingIn -> takeoff starts in `OnScreenFadeFinished(FadingIn)`; otherwise on the first run flow tick (level 1 from the menu, direct start, restart). Takeoff: [[sys-objectives-shuttle]]. Log lines (LogRogueRigs): `URRRunFlowSubsystem: arrival extractor <Name> placed on (ax, ay), footprint W x H from (minx, miny), start cell (sx, sy), screen up (dx, dy), N block cells under it, frame F; takeoff waits for the fade in|when the level plays.` and `... arrival extractor <Name> takeoff started on (ax, ay) (trigger: fade in finished|level start), frame F; world playing|paused, controls free|held, miner <location>.` Verified: build, -game log with `rr.Run.NextLevel` (takeoff in the fade-in-finished frame), direct level 1, tests Extraction.* and RunFlow.* 9/9. Not verified: map-travel fallback path.
  - `ArrivalDistanceCells` (`FRRRunFlowConfig`, int32, default 1, ClampMin 1, provisional, owner "1 cell"): read as the nearest footprint row being the next row; 2 would mean one empty cell: to confirm with the owner.
  - Run end listeners (task-211-01): `OnRunEnded` silences the subtitles for the rest of the world ([[sys-subtitles]]) and makes the HUD call `ShowEndScreen` (`URRHUDWidget::OnEndScreenShownDelegate` / `OnEndScreenShown`, the event the bp widgets bind to hide every HUD element but the end screen, [[sys-hud]]); the miner death does the same through `ARRGameMode::OnGameOver`.
  - `FRRRunFlowConfig` (`RRRunFlowConfig.h`): `AlertFillSeconds` 240, `KillAlertSeconds` 0.5, `ConsoleAlertThreshold` 0.4, `ConsoleMinDistanceCells` 36, `ConsoleMaxDistanceCells` 60 (task-029-04: 12–20 cells of 200 uu × 3), `bPreferCellsWithMarkedRocks` true, `ConsoleClass` (none = native `ARRConsole`); extraction ([[extraction]]): `ShuttleMinDistanceCells` 37 and `ShuttleMaxDistanceCells` 50 (task-049-01; was at least 75, no maximum; a max below the min counts as the min), `ShuttleCountdownSeconds` 45, `ShuttleBoardRadiusCells` 12 (804 uu; was 3 = 201 uu, x4 with the extractor scaled x4, task-375-01, 8fae3518, owner 2026-10-29, provisional), `ShuttleClass` (none = native `ARRShuttle`; the BP agent sets the shuttle Blueprint); bonus chest (task-056-01): `BonusChestAlertThreshold` 0.6 (0 = no chest), `BonusChestMinDistanceCells` 30, `BonusChestMaxDistanceCells` 45, `BonusChestClass` (none = native `ARRBonusChest`). Edited on `BP_RRGameMode` (`ARRGameMode::RunFlowConfig`), read on the first tick; `SetConfig` overrides (tests).
- arrival footprint switch (task-372-01, de889932, 0e85c9a0): `SetArrivalClearsFootprint(bool)` / `DoesArrivalClearFootprint()` on `URRRunFlowSubsystem`, default on; off, `PlaceArrivalShuttle` still places the extractor but the blocks stay. The extraction landing clear is not affected. Details: [[sys-objectives-shuttle]].
