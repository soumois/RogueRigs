# Objectives — shuttle

  - `ARRShuttle` (Blueprintable, not abstract): spawned on a random reachable Floor cell (footprint clear) straight-line `ShuttleMinDistanceCells`–`ShuttleMaxDistanceCells` from the miner cell (fallbacks above; no reachable cell: retried each tick). Countdown `ShuttleCountdownSeconds` (cheat `ShuttleCountdownOverride` > 0 replaces it at landing, [[sys-cheats]]). Each tick (not paused): miner alive within the board radius (2D) → extracted (win); else countdown −dt, at 0 → missed (loss). Dead miner freezes it. Robots keep spawning meanwhile ([[sys-spawner]] is independent). Mesh NoCollision.
  - Visual components (task-369-02, bc6422d1): `Mesh` is the extractor body; protected `RotorFL`, `RotorFR`, `RotorRL`, `RotorRR` (`UStaticMeshComponent`, VisibleAnywhere, BlueprintReadOnly) are attached to `Mesh`, NoCollision, no overlap events, no navigation impact, empty mesh and zero location until the Blueprint fills them ([[bp-extraction-shuttle]]). Public BlueprintPure `GetRotors()` returns them in the order FL, FR, RL, RR. Board radius: 12 cells = 804 uu since task-375-01 (rule unchanged; [[sys-objectives-run-flow]]). Tests RogueRigs.Extraction and RunFlow 8/8, Integration.FineConsoleShuttlePlacement pass.
  - Takeoff (task-370-01, 2e1bde02): `StartTakeoff()` (BlueprintCallable, category Shuttle|Takeoff; no-op if already taking off; callable from C++, reserved for the arrival of task-371), `IsTakingOff()`, `GetTakeoffSeconds()`. It sets `SetTickableWhenPaused(true)` only then, so the shuttle ticks while the game is paused behind the end screen; the countdown and board rule stay stopped. Phases: spin-up `SpinUpSeconds`; vertical rise `RiseHeight` over `RiseSeconds` (smooth ease); nose-down tilt of `PitchDegrees` over `TiltSeconds`; then flight speed grows by `ForwardAcceleration` × dt × tilt alpha along the nose (+X). Removal once, after the tilt, none of the 8 bounds corners projects inside the player 0 viewport (or `TakeoffMaxSeconds` elapsed): `OnTakeoffFinished` event, delegate `OnShuttleTakeoffFinished(ARRShuttle*)`, then `Destroy`. Blueprint events `OnTakeoffStarted` and `OnTakeoffFinished` (BlueprintImplementableEvent) are where the Blueprint spins the rotors and plays the wash; not implemented yet in [[bp-extraction-shuttle]].
  - Takeoff tunables (EditDefaultsOnly on `ARRShuttle`): `SpinUpSeconds` 0.5, `RiseHeight` 400 uu, `RiseSeconds` 1.5, `PitchDegrees` 20, `TiltSeconds` 0.4 (first five from the owner request, [[extraction]] Q3 values); `ForwardAcceleration` 1500 uu/s², `TakeoffMaxSeconds` 12, and the removal rule: provisional choices of the cpp agent, not in the gdd, need owner confirmation.
  - Hidden miner (task-370-01): `EndRun(true)` calls `ARRMiner::HideForExtraction()` then `StartTakeoff()` right after `EnterEndPause` (screen timing unchanged): miner and drone hidden in game, collision off, drone `ReleaseDig`. `IsHiddenForExtraction()` reads it; `ShowAfterExtraction()` undoes it and is called by `PlaceMinerAtStart` ([[sys-run-transition]]).
  - Arrival mode (task-371-01, 66b2c5e2, be525566): `InitializeArrival(Grid, Cell)` places a landed extractor at the footprint centre and sets `bArrival` (`IsArrival()`, BlueprintPure, for the Blueprint to hide chevrons or glow later); `bInitialized` stays false, so no board check, no countdown, no `OnLanded`. It takes off through `StartTakeoff()`; placement and trigger live in [[sys-objectives-run-flow]]. Not verified: whether `BP_ExtractionShuttle` shows chevrons or glow by default in arrival mode (`open`, BP work later).
  - Extractor x4 (task-375-01, 8fae3518; Blueprint b112688b): `FootprintCells` default (4, 3) -> (16, 12) (16 x 12 cells of 67 uu = 1072 x 804 uu; the hull scaled x4 covers about 12 x 12 of it; EditDefaultsOnly, API unchanged). Landing, arrival placement, `ClearExtractorFootprint` and `FindShuttleCell` read it through `GetFootprintCells()`, so they follow; the takeoff removal uses the 8 bounds corners and follows the scale; takeoff values unchanged. Tests Extraction, RunFlow, Integration.FineConsoleShuttlePlacement pass (expectations: board radius 12, footprint cell count 192); no 16 x 12 fallback warning in 5 seeds, all in the 37-50 band. Provisional, owner 2026-10-29 ([[task-375-extractor-scale-x4]]).
  - Tests: RogueRigs.Extraction.Takeoff added, OverlapWin extended.
  - Footprint clear (task-372-01, de889932, 0e85c9a0): the blocks under the footprint are destroyed before the extractor is spawned, both at the extraction landing (`LandShuttle`) and at the arrival (`PlaceArrivalShuttle`), by `ARRArenaGrid::ClearExtractorFootprint` with the footprint size from `GetFootprintCells()` (16 x 12 since task-375-01, no new tunable); resources stay on the floor ([[sys-grid-deposits]], [[sys-grid-api]] for the log line). `FindShuttleCell` prefers an open footprint, so the landing usually clears 0 blocks. Since task-376-01 (9f2c53ae) the cleared rectangle is the footprint grown by the margin (next bullet). Not verified in game: deposits, pickups and barrels under the extractor (the -game placements all had open footprints, 0 blocks).
  - Clear margin (task-376-01, 9f2c53ae): new `ARRShuttle` property `ClearMarginCells` (int32, EditDefaultsOnly, BlueprintReadOnly, default 2, ClampMin 0) with BlueprintPure `GetClearMarginCells()`; both placements destroy the rock under the footprint and in a margin of that many cells on every side (20 x 16 cells with the defaults; rect rule in [[sys-objectives-run-flow]]). Landing cell choice, `FindShuttleCell`: (1) a random cell of the 37-50 band whose 16 x 12 footprint is open; (2) else a random reachable floor cell of the band, its rock destroyed at landing; (3) the old out-of-band fallbacks only when the band has no reachable cell. It logs the candidate counts. Margin 2 cells provisional, owner 2026-10-29 ([[task-376-extractor-rock-margin]], Q4, Q5).
  - Rotor spin (task-373-01, d88a3adf): every tick, before the takeoff or board logic, `TickRotors` turns each rotor with `AddLocalRotation` about its local Z, also while paused once `StartTakeoff` set tick-when-paused. Directions seen from above: FL and RR clockwise, FR and RL counter-clockwise (tunables `bRotorFLClockwise` true, `bRotorFRClockwise` false, `bRotorRLClockwise` false, `bRotorRRClockwise` true). Speed: `GroundRevPerSecond` 3, `FlightRevPerSecond` 5 (from `StartTakeoff`), linear ramp `RampSeconds` 0.5 (0 = instant); EditDefaultsOnly, owner 2026-10-29 ([[extraction]] Q6), provisional.
  - Rotor API (category Shuttle|Rotors): `GetRotorRevPerSecond()` (BlueprintPure, current rev/s); `GetRotorSpeedAlpha()` (BlueprintPure) = current rev/s divided by `FlightRevPerSecond`, clamped 0..1, so it is 0.6 on the ground (3/5), 1 in flight, not 0..1 from rest; 0 if `FlightRevPerSecond` is 0. `OnRotorSpeedChanged(Alpha)` (BlueprintImplementableEvent) fires each ramp frame and once at `BeginPlay`, for the rotor wash (task 374). [[bp-extraction-shuttle]] does not implement it and does not spin the rotors itself. Test RogueRigs.Extraction.RotorSpin measured 3.000 / 5.000 / 5.000 rev/s (ground / flight / paused). Not verified on screen.
