# Pickups

- responsibility: the pickup actor (pop, attraction, collection) and the drop rule of ore and heal ore blocks. XP pickups add XP on collection; Heal pickups apply a heal effect (task-034-01; amount from the ore table since task-088-02, [[heal-ore]]); Ore pickups add their `OreValue` to the run flow carried count ([[sys-objectives-ore-counter]], task-183-01).
- main_classes: `ARRPickup` (`Source/RogueRigs/Pickups/RRPickup.h/.cpp`, `Abstract`, Blueprintable), `ERRPickupType` (Ore, Heal, XP), `ERRPickupPhase` (Pop, Rest, Magnet, Collected); `URRPickupSubsystem` (`Pickups/RRPickupSubsystem.h/.cpp`, `UTickableWorldSubsystem`, Game and PIE worlds, pauses with the world) moves every pickup in one loop per frame: player 0 pawn and its `PickupRadius` read once, then `ARRPickup::UpdateMotion` per pickup (actor tick off; on only when the subsystem is missing). No physics, no collision: root `PickupMesh` `NoCollision`, no overlap, no navigation; `BeginPlay` also sets `NoCollision` and `CanCharacterStepUpOn` No on every primitive component, Blueprint ones included (task-028-03: the saved `BP_PickupXP` Trail blocked the miner, which climbed onto cubes and rock). Blueprint subclasses set `PickupType` and the mesh. Glow fade (task-148-01, provisional, owner 2026-10-13): with `bGlowFade` (default false; `GlowFadeDuration` 0.2 s, `GlowFadeDataIndex` 0) a value 0..1 written as Custom Primitive Data on `PickupMesh`: 0 in Pop, fades to 1 at the start of Rest, to 0 at the start of Magnet and Collected; advanced in `UpdateMotion` (subsystem loop) only while it moves, reset to 0 at life start and pool release ([[sys-pickups-lifecycle]]). Look per life (task-192-01, owner 2026-10-15): `ERRPickupRestOrientation` (None, YawOnly, Full) `RestOrientation` (default None) and `MeshVariants` (default empty = keep the Blueprint mesh), both drawn once per life in `StartLife`, details in [[sys-pickups-lifecycle]]. Floaty pop and mid-air magnet (task-195-01, owner 2026-10-15, provisional): `PopFallTimeRatio` (default 1 = symmetric arc; a ratio above 1 slows the fall of the main arc by a time remap, same path, same `PopDuration`) and `bAttractDuringPop` (default false) with `PopAttractDelay` (default 1.2 s from life start) letting the magnet latch mid-air through the same `TryLatchMagnet` as from Rest; values on BP_PickupXP, BP_PickupOre and BP_PickupHeal come with task-195-02 (BP_PickupXPBig keeps the short pop); details in [[sys-pickups-lifecycle]].
- drop rule (in `ARRArenaGrid`, see [[sys-grid]]): `OrePickupClass` for Ore, `HealPickupClass` for HealOre; other types drop nothing. Per cell the grid counts dig drops already spawned (`CellDigDrops`). After each `ApplyTerrainDamage` that leaves the block standing, crossed = floor((max health − health) / `DropInterval`), capped at the number of multiples strictly below max health; the difference with the count is spawned. The destroying hit spawns no dig drop; `DestroyCell` spawns `DestroyDropCount`, whatever the source. Defaults at 67 uu (task-029-04): ore and heal ore health 1.5 = interval 1.5, so no dig drop and 1 pickup at destruction (one per broken block, [[ore-blocks]]); a heal cluster of 3 × 3 gives 9 (one 200 uu heal block gave 5); since task-034-01 the drone mines the whole vein at once ([[sys-drone]]), so all 9 drop together. The former 4.5 health with 3 at destruction gave drops at 1.5 and 3.0, then 3 (5 total).
- entry_points: `ARRPickup::GetPickupType`, `GetOreValue`, `SetOreValue`, `GetPhase`, `IsMagnetized`, `GetMagnetSpeed`, `GetXPAmount`, `GetHealAmount` (BlueprintPure), `SetXPAmount`, `SetHealAmount`, `SetPopYaw`, `GetPopStart`, `GetPopEnd`; protected `IsRefusedByMiner`, `ReturnToRest`, `TryLatchMagnet`, `GetLifeElapsed`; Blueprint events `OnMagnetStart()` (trail on) and `OnCollected(Location)` (detached sparkle); `ARRPickup::IsLifeStarted`, `OnPoolAcquired`, `OnPoolReleased`; `ARRPickup::GetXPBigPickupClass`; `URRPickupSubsystem::RequestSpawn`, `RequestXPCube`, `FlushXPCubes`, `Get/SetSpawnMaxFrames`, `GetQueuedSpawnCount`, `GetPoolStats`, `GetPickupCount`, `GetMagnetizedCount`, stat `RR Pickups Tick`; `ARRMiner::GetPickupRadius()`, `OnPickupCollected`, `OnPickupCollectedAt` ([[sys-player]]).
- data: `PickupRadius` from `PlayerBaseStats.csv` ([[sys-gas-core]]); drop tunables on the grid Blueprint.
- depends_on: [[sys-grid]], [[sys-player]], [[sys-gas-core]].
- implements: [[ore-blocks]], [[heal-ore]], [[ore-economy]] (drops only), [[player-stats]] (pickup radius).
- gotchas: one subsystem loop and one 2D distance per resting pickup per frame; pooled since task-092-01 (live counts skip idle pool pickups; numbers in [[perf-stress-grid-cells]]). Stress S7 burst of 400 chasers (1200 cubes, task-027-01): avg 9.19 ms, p99 11.34 ms; the single burst frame (400 deaths + 16 barrels) 109 ms max, the known per-death burst cost. Grid ore and heal chunks use the same 80-220 uu pop: at 67 uu cells a chunk can rest over unbroken rock for its 1 s rest (a Blueprint can lower `PopMaxDistance`). A single hit that both crosses a multiple and destroys the block gives no dig drop for that multiple. Fourth test (task-034-01): heal pickups were collected (magnet, event) but healed nothing, there was no heal code; collection itself works for every type, no overlap is involved. Ore value: 1 per chunk (owner 2026-10-10), carried by `OreValue`. The ore chunk Blueprint has a trail since task-189-05 (owner 2026-10-15, overrides the earlier no-trail rule of [[ore-in-rock-plan]], task-070-02): TrailFX with NS_OreTrail activated in `OnMagnetStart`, without the XP look-at, so the random rest orientation is kept ([[bp-pickup-ore]]). Pickups spawn only in a game world. `RogueRigs.PickupPool.ReusedPickupEqualsFresh` fails since task-192-02 / task-189-05 (seen in task-195-01): the Blueprints now draw a random rest orientation per life (Full, YawOnly), so a reused pickup no longer has the fresh rotation; the test expectation is not updated yet.
