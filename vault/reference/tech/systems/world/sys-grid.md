# Grid

- responsibility: terrain data, rendering, block health and destruction.
- main_classes: `ARRArenaGrid` (`Source/RogueRigs/Grid/RRArenaGrid.h/.cpp`, Blueprintable), `ERRCellType` (Floor, Void, Rock, Ore, HealOre, SpecialOre, Barrel, Spawn), `ERRTerrainDamageSource` (Drone, Barrel, Kamikaze, Shot: projectiles, barrels only), `URRBarrelSource` (`Grid/RRBarrelSource.h`: explosion source key of one barrel cell). Reads `Content/RogueRigs/Data/Levels/<LayoutName>.json` ([[level-layout-schema]]; parser `RRLayout::LoadLayoutFile` and `FRRLayoutData` in `Grid/RRLayoutData.h`, `ERRCellType` in `Grid/RRCellType.h`, task-206-02), or on levels 2+ of a run the layout prepared by the run ([[sys-run-layout]]: game world, run in progress, prepared or in-flight layout of the current level, waited for if needed; `LayoutName` then takes its name; otherwise its own file, synchronously) and fills chunked instanced components (task-029-01): per chunk of `ChunkCells` × `ChunkCells` cells (16) and per visual type (floor, rock, ore, heal_ore, special_ore, barrel), one HISM, plus one hidden collision ISM per block type, held in `FRRGridChunkVisual` (`ChunkVisuals`, created at build when the chunk holds the type, transient). The default-subobject components (`FloorInstances`, `RockInstances`..., `RockCollision`...) are empty templates whose settings each chunk component copies. `BP_ArenaGrid` sets meshes and materials; layout and cell size come from the C++ defaults (no override in the Blueprint or in `L_ArenaM1`).
- build rules: origin = actor, floor top at actor Z, cell (x, y) center at ((x+0.5)·CellSize, (y+0.5)·CellSize). Floor instance (slab [-FloorThickness, 0]) on every non-void cell (task-230-07; before: open and barrel cells only); block instance only on block cells, spanning [0, top] (`bBlocksFillFloorSlab` false since task-230-07), else [-FloorThickness, top]; top = `BarrelHeight` for a barrel cell, `BlockHeight` otherwise (`GetCellBlockTopHeight`, task-475-01). Rock display (task-230-07): rock, ore, heal ore and special ore cells are drawn by dual-grid corner pieces ([[sys-grid-rock-pieces]]); rock and special ore have only their collision instance, ore and heal ore a crystal cluster as render instance (task-230-08, [[sys-grid-rock-damage]]); the visual-type text below holds for floor, barrels and crystals. No face is coplanar with another visible face. Render / collision split (task-012-01): the floor HISM renders and collides (BlockAll); the block HISMs only render (NoCollision, re-applied in `BuildInstances`); each block type's collision ISM (BlockAll, hidden, no shadow, remove-at-swap, same mesh) holds the same instances in the same order, always at the rest transform. Hits on blocks therefore report the collision ISM. Barrel render transform (task-107-01, `GetBlockRenderTransform`): the barrel HISM instance uses `BarrelMesh` with a uniform scale S = min(CellSize / max(bounds X, bounds Y), BarrelHeight / bounds Z) (BlockHeight until task-475-01), its bounds bottom centre (the pivot of a bottom-pivot mesh) on the cell centre at the floor top (z = 0 always, task-108-01; task-107-01 anchored it at -FloorThickness, sunk in a floorless cell); null `BarrelMesh` or zero bounds fall back to the cube transform; shake moves around this transform. Every other block, and every collision ISM including barrels, keeps the MeshBaseSize cube transform (`GetBlockInstanceTransform`). The barrel collision ISM uses `BarrelCollisionMesh` (default `/Engine/BasicShapes/Cylinder`, the barrel shape before task-107; null falls back to `BarrelMesh`), so the decorative mesh never changes barrel collision.
- lifecycle: built in `OnConstruction` (editor) and again in `BeginPlay`; `OnConstruction` is ignored once play has begun, so runtime destruction survives. A grid spawned by the asynchronous loader (`SetExternalBuild`, task-493-01) skips both and is built over frames by `BeginIncrementalBuild` / `StepIncrementalBuild`; `BuildInstances` runs the same units (prepare, cells per chunk, corner pieces per chunk, crystals, barrel shadows) in one call ([[sys-layout-loader]]).
- properties (all editable): `LayoutName` `arena_m1_fine` (240 × 240; was `arena_m1` 80 × 80, kept for the logic tests), `CellSize` 67 (was 200; task-029-04, [[arena-grid]]), `BlockHeight` 153 (task-475-01 bea54ef4, owner 2026-11-06, provisional: head top of the 0.9 miner at rest, 170 x 0.9, [[bp-miner]]; was 100; rock pieces, ore, heal and deposit crystals, block collision and the dig face follow it; the rock slab material sag clamp stays 40 uu, so a damaged top sinks to 113 at most), `BarrelHeight` 100 (task-475-01: barrel render fit and collision, the old block height, so barrels do not change with BlockHeight), `FloorThickness` 200, `bBlocksFillFloorSlab` false (task-230-07; was true), rock piece properties in [[sys-grid-rock-pieces]], `MeshBaseSize` 100; health in dig-seconds at mining speed 1 per 67 uu block (provisional, [[drone]], [[ore-blocks]]): `RockHealth` 0.65 (owner 2026-10-20, provisional, task-260-01; was 0.5, before that 1.5), `OreHealth` 2, `HealOreHealth` 2, `SpecialOreHealth` 2 (owner 2026-10-20, provisional, task-259-01; were 1.5, before that 4.5), `BarrelHealth` 0.5 (was 1.5; equal to rock until task-260-01, kept at 0.5); `BarrelShotHealth` 20 (shot damage units, separate from dig health; barrel gdd), `BarrelExplosionRow` `Barrel`; `ShakeAmplitude` 8 uu, `ShakeVerticalAmplitude` 3 uu (owner 2026-10-19, task-231-01; were 25 and 8), `ShakeFrequency` 8 Hz (owner feel feedback task-008-02 and task-011-01; not overridden in `BP_ArenaGrid`; rock pieces take them from MI_RockSlab `ShakeParams`, kept equal by hand); drops: `OrePickupClass`, `HealPickupClass` (none; set to the pickup Blueprints), `DropInterval` 2 dig-seconds (kept equal to the ore health, so no dig drop at 67 uu; 1.5 until task-259-01), `DestroyDropCount` 1 (was 3: one chunk per broken block, [[ore-blocks]]); `<Type>Mesh`/`<Type>Material`.
- destruction: removes the block instance (collision ISM, and the barrel HISM at the same index), rebuilds the 4 corner rock pieces of a piece-type cell ([[sys-grid-rock-pieces]]), adds a floor instance only when the cell has none (never since task-230-07: every non-void cell has its slab) (`CellFloorInstanceIndex` is INDEX_NONE; a barrel keeps its slab, so no duplicate) and marks that floor HISM's render state dirty (`AddCellInstance`, task-202-01: the engine HISM proxy draws the instance count it was created with, and `AddInstance` alone does not recreate it, so until the async cluster tree build finished, one or more frames later, the new slab was not drawn and the void below showed black; recreating the proxy at the end of the frame draws it at once as an unbuilt instance, as `RemoveInstance` already does; one recreation per touched chunk per frame, only on frames that break blocks), cell becomes Floor, health 0, logged Verbose by type and source. Instance maps: two cell → index arrays, `CellInstanceIndex` (block instances) and `CellFloorInstanceIndex` (floor instances), chosen by visual type (`GetInstanceIndexMap`), since a barrel cell is in both visuals; plus index → cell per chunk visual (`InstanceCells`); they serve both components of a chunk visual: they are added and removed in lockstep, both remove at swap (HISM always, the ISM through `SetRemoveSwap`), so the same index is the same cell in both. Shake moves only the rendering instance: horizontal jitter (bounded by `ShakeAmplitude`) with a vertical bob (bounded by `ShakeVerticalAmplitude`) (actor ticks only while something shakes), restored on stop; the collision instance never moves, so a shaking block never pushes the miner (`RogueRigs.Dig.ShakeKeepsCollision`).
- shadows (task-263-01, owner 2026-10-20): `bBlocksCastShadows` (EditDefaultsOnly, Grid|Rendering, default true). `CreateChunkComponent` sets `CastShadow` and `bCastDynamicShadow` to it on every component built from a block render template (rock piece ISMs from `RockInstances`, special ore; barrel HISMs never cast since task-472-01, all shadow flags off; ore and heal ore crystals too, but `bDepositCrystalsCastShadow` false, task-237-01, still turns those off after it, [[sys-grid-rock-damage]]); every floor chunk HISM gets `CastShadow` false (receives only); collision ISMs keep no shadow. Overrides the template flags (BP_ArenaGrid serializes no shadow property). Components affected on `arena_m1_fine` (225 chunks of 16 × 16): floor HISMs ≤ 225 (one per chunk holding floor) no longer cast; casters = rock piece ISMs, created lazily per chunk × set (intact, broken) × 5 shapes × variant slot (upper bound 225 × 10 × slots, only combinations present exist), plus one barrel HISM per chunk holding a barrel. Exact counts not measured. Cost (not measured): the only shadow-casting light is the miner's movable point light (task-263-02, [[lights-no-shadows]]); virtual shadow maps cache pages of static casters only while the light is still: a continuously moving local light takes the uncached path every frame (engine `VirtualShadowMapCacheManager.cpp`), so each moving frame renders the casters inside its attenuation radius (≈ 1400 uu, about 21 cells) into its cube pages; instance removal, custom data writes and the WPO shake also invalidate cached pages. Turn `bBlocksCastShadows` off to measure the difference.
- lighting channels (task-425-01, 978c15ca, owner 2026-11-04 "Tout par défaut"): `CreateChunkComponent` calls `SetLightingChannels(true, true, Template->LightingChannels.bChannel2)` on every component built from the `FloorInstances`, `RockInstances`, `OreInstances`, `HealOreInstances` or `SpecialOreInstances` template (floor chunks, ore and heal ore crystal chunks, rock and special ore dual-grid pieces, deposit crystals): channels 0 and 1, so the miner's channel 1 light ([[bp-miner]], FloorWallLight) reaches only floor and terrain blocks. Barrels and collision ISMs are untouched (channel 0 only); channel 2 follows the template. Tests: build OK, `RogueRigs.Dig` and `RogueRigs.Ore` 22/22 pass (the "RogueRigs.Grid" family named in the task node does not exist). No render check.
- rendering (task-029-01): no grid component affects navigation (no navmesh; a navigation-relevant ISM recomputed its bounds over all instances on each add or remove). `bGridAffectsDistanceFields` (true; false keeps chunk HISMs out of the mesh distance field scene, measured no gain once chunked). A destruction touches the rock (or other block) chunk and the floor chunk of its cell only. Measurements: [[perf-stress-grid-cells]].
- rules (approved): the grid is the terrain source of truth; its use for pathfinding and line of sight is provisional ([[sys-enemy-ai]]); line of sight is implemented for the shotgun. One HISM per asset type per chunk. Rock display (owner 2026-10-17, replaces the per-cell autotiling of 6 shapes by open sides): dual-grid slab pieces at cell corners, 6 shapes chosen by the 4 cells around, display only (cells, health, flow field, collision cubes unchanged); one variant per shape for now, the system supports several; design in [[rock-state-render-options]]; placement built in task-230-07 ([[sys-grid-rock-pieces]]), meshes not assigned yet. M1 grey box: one cube and one material per type ([[color-code]]).
- data: layout JSON (M1), deterministic generator (M2, [[sys-layout-generator]]). Modules Json, JsonUtilities.
- depends_on: [[sys-explosions]] (barrel destruction queues into it), [[sys-ground-telegraph]] (barrel fuse zone).
- implements: [[arena-grid]], [[destruction-rules]], [[ore-blocks]], [[explosions]] (terrain side).
- gotchas: missing file or parse error logs on `LogRogueRigs` and leaves the grid empty. The layout folder must be packaged as a non-asset directory. Moving a shaking instance dirties the HISM tree each frame (fine for a few cells). The split doubles the block instance count (collision ISMs have no cluster tree and no render cost). A Blueprint that re-enables collision on a block HISM is overridden at build. Explosions call `DestroyCellsInRadius` only from `URRExplosionSubsystem` (queued, source Barrel or Kamikaze from the CSV row; [[sys-explosions]]); the run log will react to the delegates. Autotiling and top-face variants: not implemented; the grid plays no particle at destruction (the drone plays its own debris burst, [[sys-drone-dig]]). Chaos Destruction is not used; terrain damage stays outside GAS.
- extractor footprint (task-372-01, de889932, 0e85c9a0): the extractor set on the ground destroys the blocks under its 4 x 3-cell footprint through `ARRArenaGrid::ClearExtractorFootprint` (source `Extractor`, [[destruction-rules]] item 4), before it is spawned; entry point and log line in [[sys-grid-api]], deposit and drop rule in [[sys-grid-deposits]], barrels in [[sys-grid-barrels]].

- barrel shadows (task-472-01, owner 2026-11-06 Q2, Q3 provisional): `BuildBarrelShadows` (end of `BuildInstances`) adds one `URRBlobShadowComponent` per barrel cell under `GridRoot`, on the floor top at the cell centre, footprint = drawn barrel width (at most one cell), `BarrelShadowOpacity` 0.6 and `BarrelShadowScale` 1.2 (EditAnywhere, Grid|Barrel Shadow); `DestroySingleCell` removes it with its barrel, `ClearAllInstances` destroys all; `GetBarrelShadow(Cell)`, `GetBarrelShadowCount()` ([[sys-blob-shadow]]).
