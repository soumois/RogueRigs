# Actor pool

- responsibility: hand out actors of any class, reusing released ones at once and spreading the creation of missing ones over at most MaxFrames ticks; park released actors; counters for tests and stress logs (task-090-01). Callers migrate in task-091 (robots) and task-092 (pickups).
- main_classes: `Source/RogueRigs/Pool/`: `URRActorPoolSubsystem` (`RRActorPoolSubsystem.h`, tickable world subsystem, game and PIE worlds); `IRRPoolable` (`RRPoolable.h`, BlueprintNativeEvent `OnPoolAcquired`, `OnPoolReleased`); plain structs `FRRPoolAcquireParams` (Owner, Instigator, CollisionHandling, MaxFrames, Requester, `OnInit`, `OnReady`), `FRRPoolRequestHandle`, `FRRActorPoolStats`.
- entry_points: `Acquire(Class, Transform, Params)` → handle (idle actor delivered before returning, else queued); `AcquireImmediate(Class, Transform, Params)` (synchronous, outside the budget); `Prewarm(Class, Count, MaxFrames)` (default none; level-start orders from [[sys-spawner]], task-111-01); `CancelRequest(Handle)`; `IsRequestPending`; `Release(Actor)`; `IsIdle`, `IsPoolMember`, static `IsPooledIdle(Actor)`; `GetStats(Class = null)`, `ResetStats`; `ClearPool(bDestroyIdle)`.
- delivery order: creation = `SpawnActorDeferred`, `OnInit`, `FinishSpawning` (BeginPlay), `OnPoolAcquired`, `OnReady`. Reuse = owner, collision, transform (scale = requested scale × the root template scale recorded at creation, as a spawn multiplies them: task-095-01, BP pickups have a 0.3 PickupMesh root and came back 3.3× bigger), visibility, default ticks restored, then `OnInit`, `OnPoolAcquired`, `OnReady`. Release = `OnPoolReleased`, hidden, collision off, actor and component ticks off, timers of the actor cleared, owner cleared.
- spread: each tick serves reuse first (free), then creates, earliest deadline first, max over k of ceil(requests due within k ticks / k): one batch of N with MaxFrames M creates ceil(N / M) per tick. Prewarm (task-111-01): creation i of a batch is due on tick ceil((i + 1) × M / N) and runs on that tick only (just in time; not counted in the budget before), ties broken by the exact fractional deadline, so a batch spans exactly M ticks at most ceil(N / M) per tick even beside other batches: 30 over 20 = 1 or 2 per tick, 5 over 60 = one every 12 ticks (measured in `RogueRigs.PoolPrewarm.*`). Before, all of a batch shared the deadline M, so it was created as fast as the budget allowed (5 over 60 in 5 ticks) and two equal batches ran one after the other. Ticks after the actor tick groups, so a request from an actor tick with MaxFrames 1 is served the same frame. A request whose `Requester` dies is dropped without callback.
- caller contract (tasks 091, 092): implement `IRRPoolable`: `OnPoolAcquired` resets per-life state (BeginPlay runs only once: health, death flags, scale, registration in subsystems such as `URRPickupSubsystem`), `OnPoolReleased` stops activity and unregisters. Replace `Destroy` with `Release`. Keep the handle and cancel it when the requester stops (miner death, level end). Systems that enumerate or count live actors skip `IsPooledIdle(Actor)` (spawner `AliveEnemies` only holds delivered robots; actor iterators must filter).
- data: none (MaxFrames comes from each caller's tunables; prewarm counts and frames on [[sys-spawner]]).
- depends_on: none.
- implements: [[perf-trace-real-game]] recommendations 2 and 3 (pool robots, pool XP cubes).
- callers: robots (task-091-01, [[sys-spawner]] `SpawnMaxFrames` 20, [[sys-enemies-base]] reset hook); pickups (task-092-01, [[sys-pickups]]: XP cubes, ore and heal drops through `URRPickupSubsystem`, `SpawnMaxFrames` 3, requester = the pickup subsystem, released on collection; task-110-01: merged big XP blocks are another pooled class acquired the same way, with the same root template scale rule; game 250: 433–587 created and about 2500 reused per 60 s, longest wait 3 frames; S7 burst 1200 cubes created 400 per frame). Measured in [[perf-stress-grid-cells]] (game 250): about 325 robots created and 809 to 863 reused per 60 s window, longest wait 15 to 16 frames.
- niagara pool (task-167-01): `URRNiagaraPoolSubsystem` (`Pool/RRNiagaraPoolSubsystem.h`, plain world subsystem, game and PIE worlds, no tick) keeps one `FRRNiagaraSystemPool` per `UNiagaraSystem` asset (free and in-use components, cap, created and skipped counters). `Spawn(System, Location, Rotation, Cap = 40, BeforeActivate)` takes a free component, else creates one below the cap, else reclaims in-use components that are not active and not waiting to start (never started under `-nullrhi`, scalability), else returns null and counts a skip; it places the component, runs `BeforeActivate` (set user parameters, arrays included, there), then `Activate(true)`. Waiting to start (task-194-01, `IsWaitingToStart`): engine 5.8 `UNiagaraComponent::ActivateInternal` leaves a component whose system is not ready (editor compile, PSO precache with DelayActivation) inactive with its component tick on, and the tick activates it once ready; every other inactive exit turns the tick off. Before task-194-01 such components counted as idle: in S7 burst 200 the first 80 debris components all waited for the first-use editor compile of the GPU NS_RobotDebris (log: after Activate active 0, tick 1, no instance; the 81st death reclaimed all 80 and re-activated them with new parameters), so the counter said 200 plays and 0 skips while 80 effects played (all 80 finished together 5.0 s later); a warm second burst in the same process played active at once. `Prewarm` now also starts the deferred editor compile in the background (`PollForCompilationComplete`, `WITH_EDITORONLY_DATA`, non-blocking; nothing in cooked builds), so the compile lands at level load, not on the first death. `OnSystemFinished` puts the component back on the free list; components are never destroyed per effect (world end: `Deinitialize` destroys them). `Prewarm(System, Count, Cap)` creates free components up to Count. Components: owned by the world settings, absolute, auto-activate and auto-destroy off, unattached. Counters `GetInUseCount`, `GetComponentCount`, `GetCreatedCount`, `GetSkippedCount`, `GetRequestedCount` (`Spawn` calls, played or not: task-432-01), `GetPlayedCount` (components playing or waiting to start after `Activate`; one that completed inside `Activate`, e.g. pre-culled, is not counted: task-181-01, task-194-01); `GetPooledSystems` lists the systems that have a pool (stress step line, [[sys-stress-diagnostics]]). The cap is per system and comes from each caller (last value wins); systems must be one-shot. Callers: robot death puff ([[sys-enemies-base]] `DeathPuffSystem`, 40); robot debris (task-166-02, [[sys-enemies-base]] `DebrisSystem`, cap `DebrisPoolSize` 40, prewarmed at BeginPlay, user arrays and `User.HitDirection` set in `BeforeActivate`); player shot impact sparks (task-432-01, [[sys-projectiles]] `ImpactSparkSystem`, cap `ImpactSparkPoolSize` 24, prewarmed by `ARRWeapon::Acquire`, no user parameter); drone dig debris (task-438-01, [[sys-drone-dig]] `DigDebrisSystem`, cap `DigDebrisPoolSize` 16, prewarmed by `SetOwnerMiner`); explosion wall debris (task-439-01, [[sys-explosions]] `WallDebrisSystem`, cap `WallDebrisPoolSize` 8, prewarmed at `OnWorldBeginPlay`). Reuse turns collision on before the transform is restored: a caller that shrinks its actor must restore its scale in `OnPoolReleased` (robots do; otherwise Chaos ensures NewMP.Mass > 1e-8, a 3 s hitch). `Release` refuses actors not created by the pool, already idle, or being destroyed (warning). Members destroyed by anyone leave the pool (`OnDestroyed`). Verified (task-194-01, editor `-game`, L_ArenaM1, `Saved/Stress/task194_*.log`, not committed): S7 burst 200 chasers twice in one process, before the fix 200 plays / 0 skips then 64 / 120; after it 80 / 120 both bursts, all 160 active at once, the debris compile logged at frame 2 (level load), first burst max frame 72 ms against 139 (throttled PC, indicative only); game mode cap 200 (settle 20, measure 30): debris 219 plays, 18 skips. Verbose `LogRogueRigs` logs each play (active, waiting), reclaim and skip. DontSpawnIfColliding is not honoured on reuse. World end: `Deinitialize` drops pending requests without callbacks and leaves idle actors to the world.
