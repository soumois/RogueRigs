# Damage numbers

- responsibility: every floating damage number of a world, from hit to Niagara particles (task-025-01). No actor per hit.
- main_classes: `URRDamageNumberSubsystem` (`Damage/RRDamageNumberSubsystem.h/.cpp`, `UTickableWorldSubsystem`, Game and PIE worlds only), structs `FRRDamageNumber` (Location, Value, bCritical, Size, Color, SpawnTime; one per number) and `FRRDamageDigit` (Location, Digit 0–9, Size, Color, bCritical, SpawnTime; one per drawn sprite, task-025-04); `URRGameUserSettings` (`Settings/RRGameUserSettings.h/.cpp`, `UGameUserSettings` subclass, `bShowDamageNumbers` saved in the user's GameUserSettings.ini; `Config/DefaultEngine.ini` `[/Script/Engine.Engine]` `GameUserSettingsClassName=/Script/RogueRigs.RRGameUserSettings`).
- merge: `AddHit(Target, Value, bCritical, Location)` adds to the target's open entry while world time − first hit < `MergeWindow`, else opens one with a random horizontal jitter. Merged value = sum, critical if any hit was. The entry keeps the last hit location, so a robot that dies or is destroyed keeps its number where it was hit. Value ≤ 0 ignored; a null target never merges. Crowd stacking (task-027-01, [[damage-numbers]]): a new entry whose screen footprint (digits x `DigitAdvance` x size wide along `DigitDirection`, size tall along `StackDirection`) overlaps another open (pending) entry is lifted along `StackDirection` just above it, `StackGap` apart, at most `MaxStackSteps` times; the offset is kept for its later hits. Since task-027-03 numbers already pushed and still on screen (pushed less than `DisplayLifetime` ago) are obstacles too: every obstacle is compared where it will be when the new number appears (its push + `MergeWindow`), risen by `RiseVelocity` since its own push (fixes two white numbers of one robot overlapping, Juice_06). Safe inside a GE execution (no spawn, no broadcast).
- push: each tick, due entries (oldest first, at most `MaxNumbersPerTick`; the rest wait one tick) become `FRRDamageNumber`s (size `NumberSize`, × `CriticalScale` on a crit; `NormalColor` / `CriticalColor`), are laid out into digits by `AppendDigits` (value rounded, at least 1, at most `MaxDigits` nines; most significant digit first, left to right along `DigitDirection`, `DigitAdvance` × size apart, centred on the number position), the batch id is incremented, the digits are written to the Niagara component and the numbers broadcast by the native `OnNumbersPushed`. Ticks without due numbers write nothing. Pauses with the world.
- Niagara: one persistent `UNiagaraComponent` created at world BeginPlay at the origin (owner world settings, absolute transform, not attached, no auto-destroy), built by hand like `SpawnSystemAtLocation` so it also exists in a process that cannot render (activated only when `FApp::CanEverRender`); a push reactivates it when its system completed; unset or missing package = nothing rendered, the merge still runs. Per-digit user parameters and emitter recipe: [[sys-damage-numbers-niagara]]. At BeginPlay the asset's exposed parameters are checked: missing ones are logged once (`LogRogueRigs` Warning) and never written.
- entry_points: `ARREnemy::HandleDamageReceived` (capsule top + `DamageNumberHeight` 40, [[sys-enemies-base]]); `AreNumbersShown`, `GetPendingCount`, `GetMergeWindow`, `GetNiagaraComponent`, `GetTotalPushedCount`, `GetParticleStats` (tests and `rr.Debug.Shots`), `AppendDigits`, `GetLastDigits`, `GetDigitBatchId`; `LogRogueRigs` Verbose line per push (batch id, digit count); `URRGameUserSettings::GetRRGameUserSettings`, `SetShowDamageNumbers` (effect at once; `SaveSettings` keeps it), `GetShowDamageNumbers`.
- data: config properties, `DefaultGame.ini` section `[/Script/RogueRigs.RRDamageNumberSubsystem]`: `NumberSystem` (default `/Game/RogueRigs/FX/NS_DamageNumbers.NS_DamageNumbers`), `MergeWindow` 0.25, `NumberSize` 60, `CriticalScale` 1.6, `NormalColor` white, `CriticalColor` (1, 0.55, 0.08) (gold, owner-confirmed, task-027-01), `StackDirection` (0.766, 0, 0.643) (screen up of the camera at pitch -50, yaw 0), `StackGap` 4, `MaxStackSteps` 4 (0 = off), `DisplayLifetime` 0.7 s and `RiseVelocity` (0, 0, 85.7) (NS_DamageNumbers values; at BeginPlay `ReadDisplayFromSystem` replaces them only with a direct `InitializeParticle.Lifetime` and a non-zero `Particles.Velocity` spawn-script constant: the asset has neither (its random-range Lifetime Max is a stale 1.75 s, its rise is not a velocity constant), so the config values hold; `GetDisplayLifetime`, `GetRiseVelocity`, `IsDisplayReadFromAsset`, `GetDisplayedCount`), `Jitter` 25, `MaxNumbersPerTick` 64 (≤ 320 digits per batch), `DigitAdvance` 0.62, `DigitDirection` (0, 1, 0) (screen right of the top-down camera at yaw 0), `MaxDigits` 5.
- depends_on: [[sys-damage]] (`OnDamageReceived`); `Niagara` private module dependency ([[build-toolchain]]).
- implements: [[damage-numbers]].
- gotchas: toggle off drops open entries on the next tick and ignores new hits. Tests `RogueRigs.DamageNumbers.*` ([[sys-automation-tests]]). Per-number cost: one linear scan of open entries per hit (newest first). Rise, fade, pop and glyph rendering live in the Niagara asset; layout and digit values live in C++. `DigitDirection` is fixed: a rotating camera would need it from the view.
