# Enemies

- responsibility: the robot pawns: stats, damage intake, death and XP drop, and each robot's decisions. Spawning: [[sys-spawner]].
- main_classes (`Source/RogueRigs/Enemies/`):
  - `ARREnemy` (abstract `ACharacter`, `IAbilitySystemInterface`): own `URRAbilitySystemComponent` with `URRHealthAttributeSet`, `URRMovementAttributeSet`, `URREnemyAttributeSet` ([[sys-gas-core]]); `URREnemyMovementComponent` ([[sys-flow-field]]). No controller (`AutoPossessAI` disabled, `bRunPhysicsWithNoController`, default movement mode set at BeginPlay); RVO avoidance on, orient to movement, no walking off ledges. Capsule Overlap on `Projectile` ([[sys-projectiles]]). Crowd (task-018-02): robots pass through robots; at BeginPlay `SetIgnoreOtherRobots(bIgnoreOtherRobots)` puts `RRCollisionChannels::RobotMaskFilter` (extra mask bit 0) on the capsule body and as its move-ignore mask, so only robot-robot move sweeps skip each other; channels are unchanged, so the miner, terrain, barrels, projectiles and the miner sweeps still collide with robots (shotgun, explosions, melee and the kamikaze trigger use actor iteration and distances, not physics). RVO is the only robot separation: `AvoidanceConsiderationRadius` 250 uu on CharacterMovement (engine 500), and BeginPlay writes `AvoidanceRadiusExpansion` 1.1 (engine 1.5) and `AvoidanceLockTimeAfterAvoid` 0.3 s (engine 0.2) to the world avoidance manager (robots are its only users). `FindTarget()` = first living `ARRMiner` (cached).
  - Death (single, `State.Dead` from the health set, [[sys-damage]]): movement off, velocity cut, `DisableMovement`, collision off; scale shrinks linearly to 0 over `DeathShrinkDuration` (0.15 s); then `Stats.XPValue` pickups of `XPPickupClass` spawn at the feet recorded at death, and the robot is destroyed.
  - Damage numbers: `HandleDamageReceived` (bound to the health set `OnDamageReceived`, broadcast before `OnDeath`, so the killing hit shows too) spawns one `FloatingTextClass` (`ARRFloatingDamageText`, [[sys-target-dummy]]) per hit at the capsule top + `TextSpawnHeight` with a horizontal jitter of ±`TextSpawnJitter`, then `InitDamageText` with the normal or critical color and size. Same styling as the dummy, code duplicated for now (a shared component is a later task). M1 debug-grade, one actor per hit ([[damage-numbers]]).
  - `ARRChaser` (Blueprintable): `GetState()` → `ERRChaserState` Chase, WindUp, Attack, Recover, Dead. Chase (movement on) → WindUp when the target is alive within `AttackRange` (2D, centers): movement off, meshes blink at `WindUpFlashRate` (12 Hz) for `WindUp` → Attack (one frame): if still in range, `URRGE_DamageFlat` from its own ASC, SetByCaller `Data.Damage` = `Damage` (× `AttackPower`) → Recover (movement off) until 1/`AttackRate` after the attack → Chase. Arrival distance = `AttackRange` × `ArrivalRangeRatio` (0.9 → 108 uu). Measured cadence in contact: 0.1 s, then every 1.117 s (recover 1 s + 1 frame + wind-up). Default capsule 24 × 62 (≈ 0.7 × default character).
  - `ARRKamikaze` (Blueprintable, `RRKamikaze.h/.cpp`): `GetState()` → `ERRKamikazeState` Chase, Armed, Dead; `HasDetonated`, `GetArmTime`, `GetExplosionQueuedTime`, `GetCoreScaleFactor`. Capsule 37.4 × 96.8 (1.1 × the miner's 34 × 88, [[enemy-kamikaze]] size; on the ground: flow field and avoidance unchanged). Review for the bigger body (task-012-01): contact with the miner is at 71.4 uu between centers, inside the arrival distance (75 uu) and `ArmRange` (150 uu), so it always arms before touching; `ArmRange` and `HoverHeight` (40 uu above the capsule bottom, i.e. above the floor whatever the capsule size) unchanged. The visual size comes from the Blueprint meshes under `VisualRoot` (not changed by this task). Components: `VisualRoot` (scene, on the capsule) carrying `BodyMesh` and `CoreMesh` (static meshes, no collision, meshes set by the Blueprint; eyes and logo plate attach to `VisualRoot` in the Blueprint). `VisualRoot` sits `HoverHeight` above the capsule bottom with a sine bob (`HoverBobAmplitude`, `HoverBobRate`). `CoreMesh` scale = its BeginPlay scale × growth × (1 + `CorePulseAmplitude` × sin(phase)), phase advancing at `CorePulseRate` (Armed: `ArmedPulseRate`), growth 1 (Armed: linear to `ArmedCoreScale` over `FuseTime`). Chase (movement on, arrival distance `ArmRange` × `ArrivalRangeRatio`) → Armed when the target is alive within `ArmRange` (2D, centers): movement off; committed, the fuse runs even if the miner leaves → after `FuseTime`: queues one `ExplosionRowName` explosion at its location ([[sys-explosions]], instigator and source = the robot), adds `State.Dead` itself and runs the death without XP (`DropXP` overridden), so its own explosion is refused by its ASC and never counts as a kill. Killed before (shots, another explosion): `HandleDeath` queues the same explosion and the XP drops as usual. The robot being the source, the subsystem never explodes it twice. Its explosion hits every ASC with a health set in the radius: miner, chasers, other kamikazes (which then explode in turn). Measured (300 uu/s): arms at 149.5 uu, explosion queued 0.500 s after arming, core peak ≈ 2.00 while armed.
- editable (`EditDefaultsOnly`): crowd (category `Enemy|Crowd`): `bIgnoreOtherRobots` (true), `AvoidanceRadiusExpansion` (1.1, 0 = leave the manager), `AvoidanceLockTimeAfterAvoid` (0.3 s, negative = leave); `StatsRowName` (chaser: `Chaser`), `XPPickupClass` (none by default: the Blueprint sets `BP_PickupXP`), `DeathShrinkDuration`; damage numbers (`EditAnywhere`, category `Enemy|Damage Text`): `bShowDamageNumbers` (true), `FloatingTextClass` (`ARRFloatingDamageText`), `TextSpawnHeight` (40 uu), `TextSpawnJitter` (25 uu), `NormalTextColor` (white), `CriticalTextColor` (1, 0.85, 0.45), `NormalTextSize` (60), `CriticalTextSize` (90); chaser `DamageEffectClass` (`URRGE_DamageFlat`), `ArrivalRangeRatio`, `WindUpFlashRate`; kamikaze (`EditDefaultsOnly`, `StatsRowName` `Kamikaze`): `ArmRange` 150 uu, `FuseTime` 0.5 s, `ArrivalRangeRatio` 0.5, `ExplosionRowName` `Kamikaze`, `HoverHeight` 40 uu, `HoverBobAmplitude` 4 uu, `HoverBobRate` 1.5 Hz, `CorePulseRate` 1.5 Hz, `ArmedPulseRate` 8 Hz, `CorePulseAmplitude` 0.15, `ArmedCoreScale` 1.8 (hover, pulse and growth values are code defaults, not gdd values). Mesh and eye: Blueprint subclass (kamikaze: `BodyMesh`, `CoreMesh` mesh and material, eyes under `VisualRoot`, `XPPickupClass`).
- light movement (task-018-03, category `Enemy|Performance`): CharacterMovement class is `URRRobotMovementComponent` (`RRRobotMovementComponent.h/.cpp`, set by `SetDefaultSubobjectClass`): while walking on a walkable floor, `FindFloor` reuses the last floor until the capsule has moved `FloorCacheDistance` (25 uu, 2D) from the last real check or its height changed (> 0.1 uu), or the engine forces a check (teleport, landing); `GetCachedFloorHits`. `bLightAttachedParts` (true): at BeginPlay an inherited `CharacterMesh0` with no skeletal mesh and no children stops ticking, colliding and rendering and goes fully absolute (skipped by move transform updates); other non-capsule primitives without collision stop generating overlap events. Far movement: every `MovementLODCheckInterval` (0.25 s, random phase) a walking robot farther than `FarMovementDistance` (2000 uu, 2D, 0 = off) from the miner and not rendered within `OffScreenGraceSeconds` (0.2 s) runs CharacterMovement and `URREnemyMovementComponent` at `FarMovementTickInterval` (0.1 s); back to every frame as soon as it is near or on screen; only with a game viewport (never in tests). `SetFarMovement`, `IsFarMovementActive`. The actor tick (attacks, kamikaze proximity) stays every frame. Measured effects: [[perf-risks]].
- knockback: `ARREnemy::ApplyKnockback(Velocity)` launches a living robot (`LaunchCharacter`, XY overridden, Z kept) with Velocity's XY × (1 − `GetKnockbackResistance()`, CSV value clamped to [0, 1]); ignored when dead or zero. Caller: the shotgun ([[sys-weapons]]).
- entry_points: `ARREnemy::LoadStatsRow`, `GetStats`, `SetIgnoreOtherRobots`, `IsIgnoringOtherRobots`, `SetFarMovement`, `IsFarMovementActive`, `GetHealthSet`, `GetEnemyMovement`, `IsDead`, `GetKnockbackResistance`, `ApplyKnockback`; `ARRChaser::GetState`, `GetLastAttackTime`, `GetAttackCount`; `ARRKamikaze::GetState`, `HasDetonated`, `GetArmTime`, `GetExplosionQueuedTime`, `GetCoreScaleFactor`. `ARREnemy::DropXP` is virtual.
- data: `Content/RogueRigs/Data/Tables/EnemyStats.csv` (`FRREnemyStatsRow`): MaxHealth, MoveSpeed, Damage, AttackRate, AttackRange, WindUp, XPValue, KnockbackResistance; row `Chaser` 30, 360, 10, 1, 120, 0.1, 1, 0; row `Kamikaze` 100, 300, 0, 0, 0, 0, 1, 0 (owner tuning 2026-10-02, task-012-01) (Damage, AttackRate, AttackRange, WindUp unused: the explosion comes from `ExplosionStats.csv` row `Kamikaze` (radius 312 uu, damage 30, [[sys-explosions]]), arm range and fuse are properties). MaxHealth, Health and MoveSpeed become base values; the rest stay CSV constants. KnockbackResistance is read by `ApplyKnockback`.
- depends_on: [[sys-gas-core]], [[sys-damage]], [[sys-flow-field]], [[sys-pickups]], [[sys-player]], [[sys-explosions]].
- implements: [[enemy-chaser]], [[enemy-kamikaze]], [[enemy-death]] (M1 shrink and drop).
- gotchas: the CSV is read on every spawn (cache it if spawns get frequent). The flash hides meshes (no material yet). Damage refused by i-frames still counts as an attack (Recover runs). Tests: [[sys-automation-tests]].
