# Enemy spawner

- responsibility: keep robots coming from outside the screen (M1 rule in [[enemies-index]]); count the robots it spawned that are alive.
- main_classes: `ARREnemySpawner` (`Source/RogueRigs/Enemies/RREnemySpawner.h/.cpp`, Blueprintable placed actor, ticks).
  - pacing: run clock `GetRunTime` = seconds of enabled spawning. Default: the wave director ([[sys-spawner-director]], `DirectorConfig.bEnabled`). Older timers when it is off: trickle (run time < `TrickleDuration`): one `TrySpawnEnemy` every `SpawnInterval`. Pack phase (`IsInPackPhase`): one `TrySpawnPack` as the phase starts, then every `PackInterval`; between packs, every `SpawnInterval` (timer reset by each pack), a lone `TrySpawnEnemy` with chance `LoneSpawnChance` (defaults: two rolls per gap, about one lone robot every 5 gaps).
  - pack: one candidate scan; size drawn in [`PackSizeMin`, `PackSizeMax`], clamped to the free slots (`MaxAlive` − alive); candidates split by side of the view rectangle (`GetSideOfRectangle`: axis of the larger gap, X on a tie); side drawn uniformly among sides with at least that many cells, else the side with the most; distinct random cells of that side.
  - class: `PickEnemyClass`, weighted draw among `WeightedEnemyClasses` entries with a class and a weight > 0; `EnemyClass` when none is valid. Per-class cap (task-022-01): an entry whose `MaxAlive` > 0 is left out of the draw while that many robots of its class (IsA) from this spawner are alive (`GetAliveCountOfClass`), its weight going to the others; every valid entry capped = no spawn (no `EnemyClass` fallback). Every draw uses the spawner `FRandomStream` (new seed in BeginPlay; `SeedRandomStream` for tests).
  - pool (task-091-01, [[sys-actor-pool]]): every spawn (lone, pack, director wave, horde) is an `Acquire` with `MaxFrames` = `SpawnMaxFrames` (20, owner 2026-10-10; 0 = `AcquireImmediate`, used by tests), requester the spawner, AdjustIfPossibleButAlwaysSpawn, same cell and transform as before. A released robot is delivered at once; a missing one is created by the pool within 20 frames (a wave of N: ceil(N / 20) per frame). A robot joins the alive list only on delivery (`OnReady`, fresh recycling state); until then it is pending (`GetPendingCount`) and holds a slot: caps use `GetOccupiedCount` (alive + pending), per-class caps count pending robots of the class, so `MaxAlive` is never exceeded. `TrySpawnEnemy` / `TrySpawnPack` return delivered robots only; `FRRSpawnedPack::Queued` counts the others (`GetCount`). `EndPlay` cancels pending requests (`CancelPendingSpawns`). Without a pool (non-game world): `SpawnActor` as before.
  - prewarm (task-111-01, owner 2026-10-12, [[sys-actor-pool]]): place = the spawner `Tick`, when `bPrewarmPools` and the cheat-free console variable `rr.Pool.Prewarm` (1; the test harness sets 0) are on, after `PrewarmStartDelayFrames` (1) ticks: queued on the second spawner tick, once (`QueuePoolPrewarm`, `HasQueuedPoolPrewarm`), whether spawning is enabled or not. The grid is built in its BeginPlay (loading frame) and the first tick comes after every BeginPlay, so the grid exists and no creation lands in the loading frame or the first gameplay frame. Orders (`BuildPoolPrewarmOrders`, `GetPoolPrewarmCount(Class)`): each level robot class: `ChaserPrewarmCount` 30 over `ChaserPrewarmMaxFrames` 20 when its nearest native class is `ARRChaser` (the shield chaser is not), else `OtherRobotPrewarmCount` 5 over `OtherRobotPrewarmMaxFrames` 60; clamped to the class `WeightedEnemyClasses` `MaxAlive` cap when > 0 (BP heavy 3 gives 3); then each distinct `XPPickupClass` of those robots' class defaults: `XPCubePrewarmCount` 30 over `XPCubePrewarmMaxFrames` 20 (all `EditDefaultsOnly`, category Spawner|Pool, defaults = owner values). The big XP block (task-110-01) is not prewarmed (no owner value). "In the level" (`GetLevelRobotClasses`, resolved with `ResolveRobotClass`): director on: phase `SingleClass` (none with `SingleInterval` > 0 = the weighted mix), members with `CountMax` > 0 of pack types weighted > 0 by some phase, timed and (overtime on) overtime horde members and `FillClass`, `ShooterCapReplacement` (none = chaser) when a drawn pack has a shooter; director off: entries with a class and weight > 0, else `EnemyClass`. An entry weight 0 does not remove a class the director spawns (`BP_ShieldChaser` is weight 0, director only), and `MaxAlive` 0 means no cap, not absent: a class is absent when no director data and no weighted entry > 0 can spawn it. `BP_EnemySpawner` (read through its class defaults in the test): chaser 30, kamikaze 5, shooter 5, heavy 3, shield chaser 5, XP cubes 30. Prewarmed robots are pooled idle: not in `AliveEnemies`, not pending, outside `MaxAlive` and per-class caps; the first spawns reuse them (delivered at once). One spawner per level assumed (each spawner prewarms its own orders).
- cap: `MaxAlive` (80 since task-046-01); nothing spawns at `GetOccupiedCount() >= MaxAlive`; timers still run. Alive = valid, not being destroyed, not `IsDead`, not parked in the pool (pruned on query: a kill frees the slot at once).
  - candidate cell (task-031-02): walkable and reachable in the flow field ([[sys-flow-field]] `IsWalkableCell`, `GetCellDistance`), no pawn's actor location in it, center at a box distance from the view rectangle between `SpawnBandMinDistance` and `SpawnBandMaxDistance` uu; band empty: the nearest band of the same width beyond it (near edge within `SpawnBandFallbackMaxDistance`). Detour filter: cells whose walk to the miner (flow steps × cell size) exceeds `MaxPathDetourRatio` × straight distance are dropped while others remain (a robot behind rock took 7.35 s to show; now 2.25 s). Since task-041-01 the filter applies only to side and back sector cells, and to every cell while the miner is still; front sector cells (run heading below) are kept whatever their detour, so robots also wait beyond the rock the miner digs toward. Spawn at the cell center, capsule bottom `SpawnFloorClearance` above the floor top (grid actor Z), AdjustIfPossibleButAlwaysSpawn.
- run heading (task-031-02): miner (flow-field goal) location sampled every tick; heading = movement over `HeadingWindowSeconds`; below `HeadingMinSpeed` = still. While running, each lone robot, director pack and horde side draws a sector around the miner (`ERRSpawnSector` Front within `FrontHalfAngle` of the heading, Back within `BackHalfAngle` of its reverse, Side between; weights `FrontSectorWeight` / `SideSectorWeight` / `BackSectorWeight`, empty sectors left out), then spawns there: lone = random cell of the sector; pack and horde = side of a random sector cell (unused sides with room first), the pack anchored on that cell. Still: uniform as before. The older `TrySpawnPack` ignores the heading. Measured ([[sys-automation-tests]]): running, 600 lone robots 56.0 / 34.7 / 9.3 %, 150 packs 56.7 / 35.3 / 8.0 %, horde back side 4 %; still, sector shares match the cell shares.
- recycling by relocation (task-036-01, [[enemies-index]], provisional; task-032-01 destroyed the robot): every tick (spawning on or off) while `bRecycleEnabled`, each robot of this spawner counts its seconds off screen (more than `RecycleOffScreenMargin` 0 uu beyond the view rectangle) since it spawned, was relocated or last left the screen; on screen it is marked seen and the timer resets. Due when farther than `RecycleDistance` 1800 uu (2D) from the miner with `RecycleDelay` 3 s off screen if seen once, `RecycleUnseenDelay` 6 s if never seen. One `GetSpawnCandidates` scan per tick with a robot due; each takes a distinct cell drawn like a lone robot (`PickSpawnCellIndex`: heading sector, then a random cell), and `ARREnemy::RelocateTo` teleports it there (capsule on the floor), clears velocity, pending knockback and input, turns the far-movement LOD off and calls `ResetStateMachine` (chaser, heavy, kamikaze back to Chase, shooter to Approach: wind-up, telegraph, flare or aim cancelled, no explosion). Class, health, stats and attack cadence are kept; it keeps its slot (not a kill, not a spawn: caps unchanged); it then counts as never seen. No cell: it stays and retries next tick. `OnEnemyRecycled(Enemy)` fires after the move; `GetRecycledCount` (relocations), `GetRecycleSeconds(Enemy)`, `HasBeenOnScreen(Enemy)`. Measured ([[sys-automation-tests]] `Spawner.RecycleKeepsSpawnsAhead`, miner running 600 uu/s, default director): 120–210 s, 206–314 arrivals (spawned or relocated) in the front sector per 30 s vs 0–62 without (two runs); 12–16 relocations a second once the cap is full (robots spawned along the long view sides, about 2800 uu away, move again after 6 s unseen). Tests that count spawns through the alive count turn recycling off (task-034-01).
- view rectangle (world XY bounding box of the four frustum corner rays projected on the floor plane; rays above the horizon clamped to a 0.05 downward slope), first source available: `SetViewRectangleOverride` (tests; `ClearViewRectangleOverride`); the first player controller's camera manager (`GetCameraCacheView`, viewport aspect ratio); the first `UCameraComponent` of the flow-field goal actor (headless worlds). Miner camera on cell (40, 40) of the 200 uu grid: X [7217, 10223], Y [5312, 10888] (same world point as cell (121, 121) at 67 uu).
- editable (`EditAnywhere`): `EnemyClass` (none), `WeightedEnemyClasses` (`FRRWeightedEnemyClass` {`EnemyClass`, `Weight` 1, `MaxAlive` 0 = no cap}, empty in C++; target mix with the heavy: chaser 65, kamikaze 12, shooter 15, heavy 8 with `MaxAlive` 5, to be set on [[bp-enemy-spawner]] by task-022-02 (task-045-01 asks heavy `MaxAlive` 3: the cap lives only on the Blueprint, not in C++); before it chaser 70, kamikaze 15, shooter 15 (task-021-02)), `SpawnInterval` 2 s, `TrickleDuration` 30 s, `PackInterval` 6 s, `PackSizeMin` 8, `PackSizeMax` 15, `LoneSpawnChance` 0.1 per roll (chosen in task-014-01; the gdd says "rare"; these five only without the director), `MaxAlive` 150, `DirectorConfig` ([[sys-spawner-director]]), `SpawnBandMinDistance` 100, `SpawnBandMaxDistance` 500 (owner 2026-10-06; replace `ViewMargin` 3 / `MaxSpawnDistanceCells` 18, 234–1240 uu; no Blueprint or map override existed), `SpawnBandFallbackMaxDistance` 3000, `MaxPathDetourRatio` 1.5 (approved provisional by the owner), `HeadingWindowSeconds` 1, `HeadingMinSpeed` 150 uu/s (miner walks 600), `FrontSectorWeight` 55, `SideSectorWeight` 35, `BackSectorWeight` 10, `FrontHalfAngle` 45, `BackHalfAngle` 45, `bRecycleEnabled` true, `RecycleDistance` 1800, `RecycleDelay` 3 s, `RecycleUnseenDelay` 6 s, `RecycleOffScreenMargin` 0, `bEnabled` true, `SpawnFloorClearance` 2 uu. Provisional ([[enemies-index]]).
- entry_points: `GetPendingCount`, `GetOccupiedCount`, `GetLevelRobotClasses`, `BuildPoolPrewarmOrders`, `GetPoolPrewarmCount`, `QueuePoolPrewarm`, `HasQueuedPoolPrewarm`, `Get/SetSpawnMaxFrames`, `CancelPendingSpawns`, `TrySpawnEnemy`, `TrySpawnPack` (ignore timers and enabled flags), `PickEnemyClass(const FRandomStream&)`, `PickEnemyClass()` (spawner stream), `GetAliveCountOfClass`, `SeedRandomStream`, `GetRunTime`, `IsInPackPhase`, `GetSpawnableClasses` (used by [[sys-stress]]), `GetAliveCount`, `GetAliveEnemies`, `IsSpawningEnabled`, `SetSpawningEnabled`, `GetViewRectangle`, `GetSpawnCandidates`, static `ProjectViewOnFloor`, `ComputeCameraViewRectangle(World, FloorZ, FallbackCameraOwner)` (the camera part of the view rectangle without override; also the shooter's on-screen test, [[sys-enemies-shooter]]), `GetDistanceToRectangle`, `GetSideOfRectangle` (`ERRSpawnSide`), static `GetSectorOfPoint`, `GetRunHeading`, `GetRunSpeed`, `GetSpawnSector`, `SetHeadingOverride` / `ClearHeadingOverride` (tests), recycling queries above; `ARREnemy::RelocateTo` ([[sys-enemies]]). Director API and delegates: [[sys-spawner-director]]. Console: `rr.Spawner.Enabled 0/1` (cheat).
- data: none (tunables on the actor). Threat-driven spawn rate: open ([[difficulty]]).
- depends_on: [[sys-flow-field]], [[sys-grid]], [[sys-enemies]], [[sys-player]] (camera).
- implements: [[enemies-index]] M1 spawn rule.
- gotchas: a queued robot appears up to 20 frames (about 0.25 s at 80 fps) after its cell was chosen off screen; a fast run may bring the nearest band row to the screen edge meanwhile. One full-grid scan (240 × 240, 1.13 ms measured in [[stress-grid-cells]]) per single spawn or per pack. A side with fewer cells than the pack (arena edge) gives a smaller pack; other sides do not fill it. The bounding box of the trapezoid is wider than the near screen edge. Pawn occupancy uses actor locations only. No candidate logs Verbose and skips. Tests: [[sys-automation-tests]].
