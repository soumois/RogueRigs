# Spawner — pool prewarm

  - pool (task-091-01, [[sys-actor-pool]]): every spawn (lone, pack, director wave, horde) is an `Acquire` with `MaxFrames` = `SpawnMaxFrames` (20, owner 2026-10-10; 0 = `AcquireImmediate`, used by tests), requester the spawner, AdjustIfPossibleButAlwaysSpawn, same cell and transform as before. A released robot is delivered at once; a missing one is created by the pool within 20 frames (a wave of N: ceil(N / 20) per frame). A robot joins the alive list only on delivery (`OnReady`, fresh recycling state); until then it is pending (`GetPendingCount`) and holds a slot: caps use `GetOccupiedCount` (alive + pending), per-class caps count pending robots of the class, so `MaxAlive` is never exceeded. `TrySpawnEnemy` / `TrySpawnPack` return delivered robots only; `FRRSpawnedPack::Queued` counts the others (`GetCount`). `EndPlay` cancels pending requests (`CancelPendingSpawns`). Without a pool (non-game world): `SpawnActor` as before.
  - prewarm (task-111-01, owner 2026-10-12, [[sys-actor-pool]]): place = the spawner `Tick`, when `bPrewarmPools` and the cheat-free console variable `rr.Pool.Prewarm` (1; the test harness sets 0) are on, after `PrewarmStartDelayFrames` (1) ticks: queued on the second spawner tick, once (`QueuePoolPrewarm`, `HasQueuedPoolPrewarm`), whether spawning is enabled or not. The grid is built in its BeginPlay (loading frame) and the first tick comes after every BeginPlay, so the grid exists and no creation lands in the loading frame or the first gameplay frame. Orders (`BuildPoolPrewarmOrders`, `GetPoolPrewarmCount(Class)`): each level robot class: `ChaserPrewarmCount` 30 over `ChaserPrewarmMaxFrames` 20 when its nearest native class is `ARRChaser` (the shield chaser is not), else `OtherRobotPrewarmCount` 5 over `OtherRobotPrewarmMaxFrames` 60; clamped to the class `WeightedEnemyClasses` `MaxAlive` cap when > 0 (BP heavy 3 gives 3); then each distinct `XPPickupClass` of those robots' class defaults: `XPCubePrewarmCount` 30 over `XPCubePrewarmMaxFrames` 20 (all `EditDefaultsOnly`, category Spawner|Pool, defaults = owner values). The big XP block (task-110-01) is not prewarmed (no owner value). "In the level" (`GetLevelRobotClasses`, resolved with `ResolveRobotClass`): director on: phase `SingleClass` (none with `SingleInterval` > 0 = the weighted mix), members with `CountMax` > 0 of pack types weighted > 0 by some phase, timed and (overtime on) overtime horde members and `FillClass`, `ShooterCapReplacement` (none = chaser) when a drawn pack has a shooter; director off: entries with a class and weight > 0, else `EnemyClass`. An entry weight 0 does not remove a class the director spawns (`BP_ShieldChaser` is weight 0, director only), and `MaxAlive` 0 means no cap, not absent: a class is absent when no director data and no weighted entry > 0 can spawn it. `BP_EnemySpawner` (read through its class defaults in the test): chaser 30, kamikaze 5, shooter 5, heavy 3, shield chaser 5, XP cubes 30. Prewarmed robots are pooled idle: not in `AliveEnemies`, not pending, outside `MaxAlive` and per-class caps; the first spawns reuse them (delivered at once). One spawner per level assumed (each spawner prewarms its own orders).
