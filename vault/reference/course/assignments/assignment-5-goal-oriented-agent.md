# Assignment 5 — Goal-oriented coding agent

## Brief
Build a coding agent that reads the GDD, scans the existing codebase, detects missing features on its own, decides what to build and in which order, and writes the code. The starter code is deliberately minimal: the point is the reasoning layer. Tools and approach are free. Estimated effort: 6 to 10 hours.

## Deliverables
1. The agent's source code.
2. A working feature in the capstone game, generated by the agent and running. A submission not connected to the capstone game gets no credit.
3. A short README: which feature the agent built, why it chose it, what the owner changed before accepting it.

## Rubric (10 points)
| Criterion | Points | Expected |
|---|---|---|
| Working feature | 4.0 | runs in the capstone; the reviewer can clone, run and see it; comes from the GDD, not invented for the assignment |
| Agent code | 3.0 | reads the GDD, scans the codebase, generates code; readable logic |
| Judgment and review | 2.0 | README shows the owner directed the agent, not only launched it |
| Code quality | 1.0 | generated code follows project patterns; no obvious bug; no hard-coded test values |

## Starter scaffold (course resources)
Provided: a ~30-line LLM call loop; a file scanner stub (`list_files`, `read_file`); a GDD parser stub (`extract_required_features`); an empty `priority_score()`; a print log. To build: the scoring logic, gap detection (scanned files vs GDD features), the code-writing step, the iteration loop (rescan after each write, stop when done).

## Blackboard (mandatory)
Every decision is visible to the owner: what it scored (each missing feature ranked, score and reason), what it emitted (exact prompts, context, instructions) and what it generated (code, file, decision), logged before it touches the codebase. The README must explain the agent's decisions: if the owner cannot, he was not in control.
